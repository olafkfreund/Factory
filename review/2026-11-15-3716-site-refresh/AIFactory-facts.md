## What AIFactory is today (3 sentences)

AIFactory is a web-based, spec-driven platform that turns GitHub issues into pull requests through a planner, coder and QA agent pipeline, with builds running as Kubernetes Jobs in production. It works with PFactory (signed plans), TFactory (test verification) and CFactory (task board/cockpit) and merges only when a signed contract, a TFactory verdict and green CI on the exact head commit agree, otherwise it holds for a human. Much of the last three months went into treating the coding agent as untrusted: scrubbing secrets from agent environments, taking run gates from server-held state, and locking down the Bash/git command paths.

## Themes

### 1. Gated, evidence-based auto-merge (capability + governance)

- Verified tasks auto-merge only on a TFactory verdict plus green host CI that AIFactory fetches itself for the exact head commit; a host without `TFACTORY_BASE_URL`, or a repo without CI, never auto-merges a verified task and times out to a human after 20 minutes. [v3.10.0](https://github.com/olafkfreund/AIFactory/releases/tag/v3.10.0) [#1695](https://github.com/olafkfreund/AIFactory/issues/1695)
- Legacy and from-issue tasks (no signed contract) now go through the same merge-time gate; this is stated as breaking for projects without TFactory or without CI, whose tasks no longer auto-merge. [v3.10.3](https://github.com/olafkfreund/AIFactory/releases/tag/v3.10.3) [#1697](https://github.com/olafkfreund/AIFactory/issues/1697)
- The merge gate acts only on the contract PFactory signed, stored server-side in a `trusted_contracts` table (needs an Alembic migration); a trusted task auto-merges only if built as a Job (`kubejob` with `DATABASE_URL`). Per the notes, auto-merge is held for all other hosts. [v3.9.0](https://github.com/olafkfreund/AIFactory/releases/tag/v3.9.0) [#1667](https://github.com/olafkfreund/AIFactory/issues/1667) [#1686](https://github.com/olafkfreund/AIFactory/issues/1686)
- A `human-approval` gate clears only on a GitHub review that approves the head commit, from someone other than the PR author and not a bot. Until AIFactory has its own bot identity, such tasks merge by hand. [v3.9.0](https://github.com/olafkfreund/AIFactory/releases/tag/v3.9.0) [#1663](https://github.com/olafkfreund/AIFactory/issues/1663)
- Optional GitHub App identity for PRs (`AIFACTORY_GITHUB_APP_*`): PR author becomes a bot, so a maintainer's approval can clear `human-approval`; unconfigured installs are unchanged. [v3.10.0](https://github.com/olafkfreund/AIFactory/releases/tag/v3.10.0) [#1671](https://github.com/olafkfreund/AIFactory/issues/1671)
- A task whose contract declares a production target or high risk class is held for a human on the live merge path; an unreadable contract also holds. [v3.8.1](https://github.com/olafkfreund/AIFactory/releases/tag/v3.8.1) [#1658](https://github.com/olafkfreund/AIFactory/issues/1658) [#1664](https://github.com/olafkfreund/AIFactory/issues/1664)
- Auto-merge PRs carry a "Verify evidence" section (verify verdict, TFactory vote split, floor signals); the notes say the verdict is evidence and the deterministic floor still decides. [v3.10.8](https://github.com/olafkfreund/AIFactory/releases/tag/v3.10.8) [#1863](https://github.com/olafkfreund/AIFactory/issues/1863)
- A generated autonomy matrix (`docs/docs/compliance/autonomy-matrix.md`) is built from the merge policy, and a required CI check fails any PR that changes the policy without regenerating it. [v3.8.0](https://github.com/olafkfreund/AIFactory/releases/tag/v3.8.0) Factory#1962

## Cautions for the blog and homepage

- Several shipped features are off by default or opt-in: remote MCP, route resolution, repo lint gate, agent commit trailers, the GitHub App, the runtime allowlist. Say "opt-in" or "behind flag X" where used.
- The model gateway image ships but nothing deploys it (v3.10.12 notes).
- Several 3.10.x releases are marked as behaviour changes or breaking for operators (auto-merge now needs TFactory and CI; private agent HOME; OIDC issuer matching; plan approvals read as stale once). The notes also list open gaps (for example the same-uid `/proc` window on local runners, #1724). Do not claim the agent isolation is complete.
- "Verified" in the merge text means the contract was signed by PFactory and the build ran as a Job; hosts without that hold auto-merge.
- No metrics (users, task counts, speed) are in the release notes; do not invent any. The only figures present are narrow (for example 790 MB per pod of CLI downloads removed, 21-subtask demo build took 145 minutes in v3.8.0 notes).
- Release-note wording reflects the maintainers' own claims; only four PR states were confirmed via `gh`. #1663 is not resolvable as a PR (probably an issue).
