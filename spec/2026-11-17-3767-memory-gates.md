# Spec: validation and trust gates (RFC-0021 Phase 4)

## Design

New `apps/backend/memory/gates.py` (stdlib only, plus Phase 3's `scratchpad`)
and `apps/backend/memory/trust.py`.

`trust.py`: `taint(now=None)` records a monotonic time; `tainted(now=None)` is
true for `TRUST_WINDOW = 600` seconds after the last taint. Never cleared by a
session end, so concurrent sessions can only add untrusted marks. `taint()` is
called from a new async `memory/hooks.py` `taint_hook`, registered as a
`PreToolUse` `HookMatcher` for `WebFetch` and for `WebSearch` in `core/client.py` of
all three repos (PFactory and TFactory have no web hook today; AIFactory has the
SSRF hook, the new one sits beside it), and directly from `guarded_web_fetch`
(`mcp__aifactory__web_fetch`) in AIFactory. `scratchpad.observe` callers
(failure hook, `record_dead_end`) pass `untrusted=trust.tainted()`.

`gates.py`, ordered pure functions over `list[Signal]` (a signal is one
scratchpad entry plus its kind):

1. `validation`: drop signals with `n - ab < 1` (every observation tied to an
   abandoned approach, set by `record_dead_end`'s window rule) unless kind is
   `dead_end`.
2. `frequency`: keep `n >= MIN_COUNT` (2); `dead_end` is exempt (recalled
   directly, not promoted).
3. `novelty`: drop a signal whose rendered text equals the body of an existing
   `gotchas.md` entry (exact repeat, as Phase 1) or that is already `promoted`.
4. `trust`: keep `bad == 0`; one observation made inside the untrusted window
   marks the key lower-trust and unpromotable (fails safe). The predicates differ
   from frequency on purpose, so each gate can be removed on its own.
5. `score_cap`: rank by `(n, last)` descending, keep at most `CAPS[session_type]`
   per call (Phase 2 caps still apply).
6. Synthesis: fixed form, no LLM: `Recurring <kind with underscores as spaces>
   (seen N times): <text>`.
7. Write: append as `## [timestamp]` entries to `gotchas.md` in one write, with
   the body passed through `retention.escape_headings` (the same escape
   `record_gotcha` uses, now a shared helper) so multiline text cannot forge a
   heading, mark
   the signals `promoted`, `confirm()` the bodies.

`promote(memory_dir, session_type=None, now=None) -> list[str]` runs 1-7 and
never raises. It is called at the end of `save_session_insights` (the session
end hook) for `spec_dir / "memory"`. Gate order is a list `GATES` so a mutation
check can remove one.

`record_gotcha` (explicit agent write) is not a signal and keeps the Phase 1 and
2 gates; when `trust.tainted()` its entry gets a line `_Source: unverified
(external content read in this session)_`.

Measures against section 6.1: a simulated 20-session store with 3 recurring
errors, 6 one-off errors and 2 externally-tainted repeats. Without gates (every
observation written) vs with gates: items written, exact duplicate pairs and
bytes. Reported in the PR and in an RFC section 6.2 table.

## Alternatives rejected

- Semantic novelty and LLM synthesis now: no embedder in pods; deterministic
  text keeps LLM calls from rising. RFC section 3.2 records the reduction.
- Dead ends are not promoted by these gates; recall filters untrusted ones.
- Session-scoped taint: tools do not know the session; a time window is simple
  and fails safe.
- Gating `record_gotcha` outright: loses explicit lessons; marked instead.

## Risks

- Under-promotion (a real recurring error seen only in the window after a fetch
  is not promoted): accepted, fails safe.
- Promotion writes `gotchas.md` at session end, concurrent with an agent write
  (no cross-process lock, Phase 2 gap). Graphiti write path still bypasses caps.

## Verification

`tests/test_memory_gates.py`: each gate alone, ordered pipeline, trust window,
promote writes and is idempotent, cap, `record_gotcha` unverified marker,
`save_session_insights` integration. One mutation per gate (remove it from
`GATES`) must turn its test red, plus: remove the cap, remove the marker, remove
the dead_end exemption. Measures reported as above.
