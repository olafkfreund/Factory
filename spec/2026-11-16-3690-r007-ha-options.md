# Spec: R-007 HA options for Postgres and MinIO

## Design

Add one document, `docs/compliance/r007-ha-options.md`, and link it from the
R-007 row of `docs/compliance/risk-register.md` and from the "HA Postgres
(Factory#3690)" line of `docs/compliance/dr-runbook.md`. Docs only. It holds:

1. **Facts, each with a source:** `postgres` StatefulSet `replicas: 1`
   (`factory-gitops apps/postgres/manifests/manifests.yaml`), `minio`
   Deployment `replicas: 1` (`apps/minio/manifests/manifests.yaml`), both on
   `local-path`; both k3d nodes are containers on one physical host (dr-runbook
   "single-failure-domain"); PDBs are deliberately absent (`apps/README.md`,
   Factory#550).
2. **Current RPO/RTO:** Postgres RPO up to 24h (daily 02:15 dump); restore
   checked by the `postgres-restore-drill` CronJob (configured daily; first
   recorded cluster result still pending per dr-runbook) and proven once
   manually on 2026-08-10; `rto_seconds` covers the data
   path only, the manual repoint and validation steps are unmeasured. MinIO
   evidence: versioning protects against overwrite/delete, not against loss of
   the volume or host; off-site copy is written but not deployed (Factory#3681,
   Factory#3691).
3. **Options table** with what HA each gives, what it cannot, cost, owner
   action:
   - A. Accept the risk (AR-003) and finish the off-site copy. No HA. After host
     loss, recovery uses the off-site copy: Postgres data loss is bounded by the
     newest complete dump that reached off-site storage (up to ~24h plus copy
     delay); object loss by the mirror's last successful run. RTO is an
     unmeasured estimate (rebuild cluster, restore, repoint, validate); only
     the data-restore part is measured.
   - B. Tighten Postgres RPO on the same host (hourly dump CronJob; one schedule
     line in factory-gitops). A target, not a guarantee: it needs each dump to
     complete (the job waits on MinIO and forbids concurrent runs) and to be
     copied off-site. No HA.
   - B2. WAL archiving / PITR (the register treatment names PITR). Recovers to
     a moment between dumps. Needs an archive target off the host to matter for
     host loss, and an operator or archive tooling; does not give availability.
   - C. In-cluster HA on one host (a Postgres operator such as CloudNativePG with
     2-3 instances; MinIO distributed mode). May survive a pod, process or
     rolling-upgrade failure; **does not** survive host or disk loss because
     every replica shares the one physical disk. Adds an operator and reopens
     the PDB question (Factory#550). Not a treatment for the host-loss scenario.
   - D. Second failure domain. Four distinct shapes, each needing verification
     before the owner picks one: (D1) a standby Postgres cluster on another
     host fed by streaming replication or WAL shipping, with manual or
     operator-driven promotion; (D2) a multi-host Kubernetes cluster (k3d
     cannot span hosts, so this is a migration, e.g. k3s agents on a second
     machine); (D3) MinIO site replication to a peer MinIO on another host;
     (D4) copying objects to external S3 (a backup, not HA; this is Factory#3691).
     Needs hardware or a network target and a cost decision; an agent cannot do it.
   - E. External managed Postgres and object store. Same decision class as D,
     recurring cost, own SLA.
   Whether any option reaches the register's target score of 6 is for the owner
   to reassess after it is implemented and measured.
4. **Recommendation:** A, plus B as an optional cheap tightening (a target RPO, to be measured),
   and D when a regulated tenant or customer contract needs A1.2; reviewed at a
   fixed date.
5. **Draft acceptance text** for AR-003 (risk, compensating controls with file
   evidence, review date 2027-05-16, revisit triggers), marked UNSIGNED; copy
   into `risk-register.md` only after the Security Owner decides.
6. **Owner actions** as exact copy-paste commands (off-site secret and
   kustomization line from Factory#3691, hourly schedule edit, how to record
   the acceptance), none run by the agent.

## Alternatives rejected

- **Adding PodDisruptionBudgets:** contradicts the measured Factory#550
  decision; with one replica a PDB blocks drain.
- **Adding CloudNativePG or MinIO distributed manifests (default-off):** large
  untestable change to live gitops with no failure-domain benefit on this host;
  the owner has not chosen D.
- **Editing the register to mark R-007 Accepted:** that is the owner's sign-off.
- **Rewriting dr-runbook:** it is current (scheduled drill, versioning,
  off-site status); only a link is added.

## Risks

- Document drifts from gitops. Mitigation: every fact cites a file; review date.
- The recommendation could be read as approval. It is labelled advice.
