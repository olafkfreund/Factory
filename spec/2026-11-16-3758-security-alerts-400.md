# Spec: treat a never-seen field as zero matches, visibly

## Design

In `evaluate()` (factory-gitops `apps/security-alerts/manifests/alerts.py`), on `HTTPError` 400 read
the response body (never printed) and, if it is OpenObserve's "Search field not found" error
(`"code":20004`), return `("no_field", 0)`. `no_field` is not an error: `main()` leaves rc at 0. It
is written to `job_health` with `count` 0 and is never `ok`, so the state is queryable and distinct
from a healthy zero. Every other 400, 5xx and transport error remains `error` (rc 1). The window
and `audit_chain` stream are unchanged. `not_configured` stays rc 0 (tested).

## Alternatives rejected

- Query `kind` instead of `action`: the chain forwarded today has no auth-failure `kind`, and the
  rule is defined on AIFactory's `auth.failure` action; guessing a value would be silent and wrong.
- Treat every 400 as zero: hides real query bugs, the opposite of the loud-failure requirement.
- Fail the Job on `no_field`: the Job could not succeed until an auth failure happens, so job-watchdog
  would stay critical forever for a healthy system.
- Seed a fake `auth.failure` row: writes fabricated audit data.

## Risks

A mis-spelled field name would now report `no_field` (rc 0) instead of failing. Mitigated: the status is
recorded in `job_health` and documented, and the field is a constant covered by a test on the SQL text.
