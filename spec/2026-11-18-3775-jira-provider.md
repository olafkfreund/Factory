# Spec: JiraProvider and structured Jira credential

## Design

**Hub: `providers/jira_provider.py`**, a `@dataclass` like `HttpGitHubProvider`:
`_repo` (the Jira project key), `_email`, `_api_token` (both `repr=False`),
`_base_url` (the site, e.g. `https://acme.atlassian.net`), `_issue_type`
(default `Task`), `_transport`. Basic auth, `follow_redirects=False`, 10 s timeout.
`ProviderType.JIRA = "jira"` is added (the one protocol edit; unavoidable because
`IssueData.provider` is typed by it). `jira_provider.py` joins `CANONICAL_FILES`
and a new `get_work_item_provider()` in the factory, typed `WorkItemProvider`.
`get_provider` is typed `GitProvider` (includes the code seam), so it refuses `jira` with a
pointer to the new function rather than returning a provider that lacks PR methods.
The drift checker is made tolerant of a canonical file absent from an OLD pinned tree
(consumers run the checker from `main` against their pinned canonical): it skips a file the
pinned canonical does not contain, and still fails when the canonical has it and the service lacks it.

Members:

- `fetch_issue(key)`: `GET /rest/api/3/issue/{key}`. The key is validated against
  `^[A-Z][A-Z0-9_]*-[0-9]+$` before it reaches a URL path. `number` is the key string.
- `fetch_issues`: `GET /rest/api/3/search/jql` with JQL built from the filters
  (every value quoted and escaped), always with an explicit `fields` list (the enhanced
  search returns ids only otherwise), paged with `nextPageToken` until `limit` or no token.
  `state=closed` is `statusCategory = Done`, `open` is `statusCategory != Done`.
- `create_issue`: `POST /issue`, ADF description, labels, assignee by account id,
  then a read-back. A 400 raises with the Jira field names (RFC section 8).
- `close_issue`: if the issue is already Done return True; otherwise list
  `/issue/{key}/transitions`, pick the first whose `to.statusCategory.key == "done"`,
  `POST` it (the comment rides in `update.comment` so it is one call). No such
  transition raises `JiraTransitionError` naming the available transitions.
- `add_comment`, `fetch_comments` (paged by `startAt`, `since` applied client-side
  because Jira has no server-side filter, a failed page raises `ProviderCommentError`),
  `fetch_comments_bulk` via `FanoutCommentsMixin`.
- `assign_to_user`: one assignee (Jira has one). The "Copilot" alias raises
  `NotImplementedError`. More than one raises `ValueError`.
- Labels: `apply_labels`/`remove_labels` use `PUT /issue` `update.labels`.
  `create_label` is a no-op (Jira creates a label on first use); `list_labels` reads
  `/rest/api/3/label`. Whitespace in a label becomes `-` (Jira rejects spaces).
  RFC-0011 intake on a locked-down project: a 400/403 on label apply is logged as a
  warning and degrades (returns); the intake label then simply is not set, and the
  issue is not built. 401/404/429/5xx still raise.
- `get_repository_info`: `GET /project/{key}`.
- Errors: `JiraError(httpx.HTTPStatusError)` carries a short, credential-free
  message: 401 credential rejected, 403 permission, 404 not found, 429 with
  `Retry-After`. It subclasses `HTTPStatusError` so CFactory's existing
  "credential rejected" detection keeps working.
- State: `statusCategory.key == "done"` is `closed`; any other or missing value is `open`.
- Descriptions and comments are Atlassian Document Format; a small helper converts
  ADF to text and text to paragraphs.

**CFactory**: `Settings.jira_enabled` (`CFACTORY_JIRA_ENABLED`, default false).
`validate_provider` accepts `jira` only when the flag is on, with a message naming the
flag. A jira connection requires a `base_url` (the site) and a project key. A jira
credential is sealed exactly like the others, but the plaintext is a JSON object
`{"email","api_token"}`; the PUT credential body gains an optional `email` field, required for a
jira connection and refused for the others. Read APIs keep returning only the masked
indicator. `build_provider` gets a `jira` branch that decodes the credential; it imports
the hub provider lazily, so until CFactory is re-vendored it raises a clear error.

## Alternatives rejected

- Resolution-based or per-tenant "closed" mapping: silent failure on unseen projects (RFC section 3).
- `email:token` in the single string: not rotatable in halves, not inspectable.
- No `ProviderType.JIRA` (reuse another value): mislabels every issue and breaks routing.
- Jira in CFactory only: the hub is the canonical provider layer.
- Failing label creation hard: breaks intake on locked-down projects.

## Risks

- `protocol.py` changes, so four vendored copies need a re-vendor PR after the hub merge
  (the pin must name a hub-main commit, so these cannot be green before it). Until then a
  `jira` connection with the flag on fails with a clear error; the flag stays off.
  Plan step 5 is that follow-up.
- Custom workflows with required transition fields: surfaced as an error naming the field.
- Not proven against real Jira until the owner provides a test site.
