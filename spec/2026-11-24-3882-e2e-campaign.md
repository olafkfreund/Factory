# Spec: Factory E2E test campaign

This design merges three independent proposals: Codex (gpt-6.2-sol), agy (model not reported) and Fable. Discovery facts come from the 2026-11-24 read-only exploration and were checked against working trees.

## Design

### 1. Harness: extend what exists

- **`scripts/e2e/`** is a new package that reuses `scripts/parr_regression.py` for seam checks and cleanup registration, and `scripts/benchmarks/run_pipeline_task.py` for the build stage.
- **`scripts/benchmarks/report.py`** renders the cost and model tables from each run's `run.meta.json`, unchanged.
- **One journey** is a run of (project, surface, model, repeat).
- **Stage runners** S1–S5 and X call a **surface adapter**, which has three implementations:
  - `cli`: subprocess `factory …`;
  - `mcp`: the `factory mcp` stdio client plus the per-factory MCP;
  - `ui`: Playwright, built on the Keycloak and TOTP login in `TFactory/portal_testing/run.py`.

  Each stage is then **read back through a different adapter** (MCP or REST) and through the GitHub API.
- **Host config:** one file pins the hosts. Both `*.freundcloud.org.uk` (the CLI default in `factory_cli/config.py:22-25`) and `*.freundcloud.com` serve prod. The harness uses the CLI default and records the host in `run.meta.json`.

### 2. Isolation on prod (the owner chose prod)

- **GitHub:** repos are created **by the harness**, with a fine-grained token limited to the **Freundcloud** org. They are named `e2e-<yyyymmdd>-<P#>-<run>` and tagged with the topic `factory-e2e`. The harness and the sweeper refuse every other owner or name.
  - AIFactory `POST /repos` (`routes/github.py:852`) is not used, because it runs `gh repo create` with the server's own login.
- **Factories:** a dedicated **org `factory-e2e`** in AIFactory and PFactory, with org-scoped `acw_` keys (`mcp:read`/`mcp:write`, AIF `routes/api_keys.py:86-92`), and a Keycloak test user who is a member only of that org.
  - TFactory and CFactory have no tenancy and no project-scoped keys (`TFactory` has no tenancy module; CFactory `CFACTORY_API_KEYS` keys have no project scope). There, isolation is the `e2e-` repo prefix, and read-back filters on it.
  - `X-Tenant-Id` multi-tenancy (AIF, PF and CF `tenancy.py`) is off on prod and stays off.

### 3. Model selection (gap G2)

- AIFactory takes a per-task model through `TaskMetadata.model` and `phaseModels` (`task_models.py:95-122`) and through `StartTaskRequest.model` (`execution.py:93-114`, inherited by `FromPlanRequest`). Provider IDs exist only in `routes/cli_accounts.py:43`.
- **Step 0 probe:** start a no-op P1 task with a Codex and a Gemini model id, and confirm from `GET /api/tasks/{id}/token-usage` and the logs which provider ran.
- If the model id does not route to the provider, step 1 adds an explicit `provider` field to `StartTaskRequest` (AIFactory issue).
- PFactory planning and TFactory runs stay on their default profile, and their model is recorded rather than swept. The sweep covers the coder and reviewer, where the cost is.

### 4. Fixtures (`tests/e2e/fixtures/P1..P5`)

Each fixture holds:
- a starter tree;
- an intent/spec/plan triple;
- a **hidden acceptance suite**, kept outside the repo the agents see.

| ID | Project | Size | Purpose |
|---|---|---|---|
| P1 | Python stdlib CLI `wordfreq` with pytest | XS | Canary |
| P2 | TypeScript Express API with jest, 3 endpoints | S | Model sweep |
| P3 | Go service plus a React page | M | Parallel waves, browser lane |
| P4 | Brownfield: a planted bug, a failing test and an ambiguous requirement | S | Gates, handback, mutant |
| P5 | Trap: a contradictory criterion | XS | Must end in Needs you |

### 5. Matrix: 18 journeys

| Slice | Journeys | Count |
|---|---|---|
| Surface sweep | P1 × {cli, mcp, ui} × Claude × 2 | 6 |
| Model sweep | P2 × cli × {Claude, Codex, Gemini} × 2 | 6 |
| Depth | P3 × mcp × {Claude, Codex} | 2 |
| Brownfield | P4 × ui × {Claude, Gemini} | 2 |
| Negative | P5 × {cli, ui} | 2 |

"Twice" means all three of these:
- a repeat or paired run;
- read-back on another surface;
- the hidden suite on the merge SHA after the TFactory verdict.

### 6. Stage oracles

| Stage | Pass | Must-fail probe |
|---|---|---|
| S1 onboard | Repo has branch protection; project in AIF, PF and TF; exactly one CFactory card | Replay leaves one mapping; an inaccessible repo fails visibly |
| S2 plan | `POST /api/mcp-stdio/plan/sessions/ingest-approved` accepted with valid provenance; review finding ≥ 1 on P4/P5 | A one-byte tamper gets a 4xx; replay starts no second build |
| S3 code | Terminal and green; non-empty diff only in the plan's files; review recorded; reviewer model ≠ author model | Empty or docs-only diff; done with 0 tokens |
| S4 PR | Merged by the pipeline; required checks green on the merge SHA; links intent/spec/plan; `check_merge_attribution.py` passes | A head moved after the verdict forces a re-verdict; `check_orphaned_pr_commits.py` |
| S5 TFactory | Verdict on the merge SHA with all 5 signals; hidden suite green | 0 tests collected; SHA mismatch; the P4 mutant must turn the verdict red |
| X cross-factory | One CFactory timeline event per stage, in order; rollup within ±1% of the stage sum; `cfactory_get_anomalies` empty | Duplicate or dropped completion event; CFactory#583 same-issue collision |

Every stage has a deadline. An acknowledgement without the expected state counts as a failure.

### 7. Cost

- **Fields:** each run records:
  - model requested and model actually used;
  - tokens in, out and cache;
  - `cost_usd` and `billing_mode` (metered or subscription);
  - wall time, turns and handbacks;
  - first-pass verdict and hidden-suite result.
- **Sources:**
  1. AIFactory `GET /api/tasks/{id}/token-usage` (`tasks_usage.py:29-74`, which reads `token_usage.json`);
  2. `CompletionEvent.usage` with `rollup_usage` (`factory_contracts`);
  3. the provider or gateway log where one is available.

  CFactory has no usage HTTP route: `/api/usage` is in the spec but not in code (G4), so the CFactory rollup is read through MCP `cfactory_get_rollups`.
- **Drift:** more than 5% between sources is a finding.
- **Headline:** the median cost per build that passes the hidden suite.
- **Caps:** $15 or 60 minutes per run; $450 or 8 hours per campaign. Hitting a cap aborts the run and records the abort; there are no silent retries.

### 8. Rules and skills audit

- **Followed:** checked from git and transcripts:
  - artifact order;
  - conventional commits and attribution;
  - scope;
  - `Closes #N`;
  - no pushes to main.
- **Effective:** P1 with one profile's rules and skills disabled, compared with the normal run.
- **Consistent:** CLAUDE.md, AGENTS.md and GEMINI.md are diffed across repos, and the same P2 plan is scored on a 10-item checklist for each model.
- **Scorers:** Fable scores, and Codex second-scores 20%.

### 9. RFactory

The web app is local-only today: `deploy/pod.sh up` serves 127.0.0.1:4180 through oauth2-proxy, and only `rfactory-desktops` is in gitops. The suite runs against that local instance, reading prod CFactory with an e2e read key.

- **Keycloak roles:** outsider, member, approver and admin. It fails closed when misconfigured.
- **`POST /api/standup`:** returns the right buckets with no AI call.
- **`GET /api/review` and `GET /api/review/<card>`:** a cross-project card returns 404; freshness is reported.
- **Live check:** during the P1 runs the P1 card appears. Two e2e repos with issue #1 probe CFactory#583.
- **Weekly:** a synthetic-meeting bot smoke test.

### 10. Management

- **Tracking:**
  - the Factory epic #3882;
  - one issue per campaign, `e2e-campaign-YYYY-MM-DD`;
  - each failure becomes a child issue labelled `e2e` plus its stage;
  - the `report.py` table is posted on the campaign issue.
- **Evidence:** Actions artifacts kept 30 days, passed through gitleaks first.
- **Roles:**

  | Who | Builds | Runs |
  |---|---|---|
  | **Claude** (lead) | merges | the MCP surface; triage |
  | **Codex** | the harness core and the G1 verbs | the CLI surface and the hidden suites |
  | **agy** | the UI runner and the fixtures | the UI surface |
  | **Fable** | — | reviews the oracles, runs the rules audit and adjudicates disagreements |

- **Triage classes:**
  - product bug: blocks the release;
  - surface gap: blocks the release;
  - model or skill drift;
  - infra or flake: needs 2 reproductions.
- **Cadence:**
  - nightly: the seam gate plus P1 through the CLI;
  - weekly: the campaign;
  - when a model or release changes: the model sweep.
- **Cleanup:** teardown is registered at creation. The nightly sweeper deletes only Freundcloud repos with the `^e2e-` name, the topic `factory-e2e`, and an age over 7 days, together with their factory projects and cards. It runs dry first.

## Alternatives rejected

- **A full cube (5 × 3 × 3 × 2 = 90 runs):** over budget, and it adds little over the paired slices.
- **A staging namespace:** the owner chose prod, and staging would add days of work before the first result.
- **A new runner instead of extending `parr_regression.py`:** that would duplicate the seam checks and the cleanup.
- **Self-verification by the driving surface:** it hides surface bugs, so read-back goes through a different surface instead.
- **Ollama in the sweep:** the owner excluded it.
- **Creating repos through AIFactory `POST /repos`:** it uses the server's gh login, not a scoped token.

## Risks

- **Prod contamination:** test cards appear on real boards. Mitigations:
  - the e2e org;
  - the prefix filter;
  - the sweeper.
- **Cost overrun.** Mitigations:
  - the caps;
  - XS projects first.
- **Flakiness from model non-determinism.** Mitigations:
  - oracles are hidden suites and schemas;
  - one infra retry.
- **Secrets.** Mitigations:
  - agenix only;
  - gitleaks on evidence.
- **A sweeper bug deletes real repos.** Mitigations:
  - three ANDed guards;
  - a dry run before the first live run;
  - an org-scoped token, so other orgs cannot be reached.
- **CFactory has no project scoping:** the e2e key can read every card. It is read-only and used only by the harness.

## Verification

- **The campaign checks itself:**
  - P5 and the P4 mutant must fail;
  - the tamper probe must return a 4xx;
  - read-back must agree.

  If any of these does not hold, the campaign is red.
- **Cap test:** a $0.01 cap on one P1 run must abort it cleanly.
- **Sweeper:** its dry-run list is checked by hand before the first live run.
- **Minimum viable run (step 4):** P1 through the CLI and through MCP, twice each, plus P5 through the CLI. It is green, and teardown is verified.
