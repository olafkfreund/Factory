# Spec: Plan-Slug trailer on the gitops bump (PFactory, TFactory, CFactory)

## Design

One script per repo, `scripts/plan_slug_trailers.sh [BASE]`, identical in the
three repos:

- Commits examined: `BASE..HEAD` when BASE resolves to a commit in the
  checkout, else HEAD alone.
- Per commit: `git log -1 --format=%B <c> | git interpret-trailers --parse`,
  keep `Plan-Slug: ` values (AIFactory deploy.yml line 157 logic).
- Keep a slug only if it matches `^[A-Za-z0-9._/#:-]{1,128}$` (AIFactory line
  158 regex). Deduplicate keeping first (newest) occurrence, cap at 10.
- Print one `Plan-Slug: <slug>` line per slug, nothing else. Exit 0 always:
  git errors yield empty output, so a bad trailer can never fail a deploy.

Workflow change in each `deploy.yml`, bump step only:

- Checkout of the source repo gets `fetch-depth: 0` so any pinned base exists
  (a fixed depth would silently fall back to HEAD for an old pin; Codex).
- Inside the retry loop, after the gitops clone and BEFORE `kustomize edit set
  image` (afterwards the pin is the new SHA and the range is empty), read the
  currently pinned tag from the gitops `apps/<svc>/manifests/kustomization.yaml`
  (`newTag: sha-<short>`, verified for all three), strip `sha-`, and run the
  script with `$GITHUB_WORKSPACE` as the working directory (inside `gitops` it
  would read the wrong history), with that base. The slugs are passed as data, not interpolated into shell.
- Commit message: `cd(<svc>): ${SHA} [skip ci]`, blank line, trailer lines
  (the blank line is omitted when no slug). `git commit -am` becomes
  `git commit -am "$MSG"` with `MSG` built by printf.

Base is the pinned SHA, not `github.event.before`, because `cancel-in-progress`
drops superseded runs and their commits would never be linked.

AIFactory: unchanged. Verified by running its two lines against the same
fixtures in the PR dry-run; it reads only the first trailer of HEAD, which is
correct for the squash-merge flow and needs no change. The multi-commit case is
recorded as a known limit on AIFactory#2111.

Tests: `tests/test_plan_slug_trailers.py` in each repo builds a temp git repo
with `subprocess` and asserts: HEAD trailer; none; invalid slug rejected;
two slugs in a range, deduplicated and newest first; base not in checkout falls
back to HEAD; non-git directory exits 0 with empty output. pytest already runs
in each repo's CI, so no new job.

## Alternatives rejected

- Shared composite action or reusable workflow: the three deploy workflows
  are self-contained; a per-repo script is the smallest change and testable.
  (`workflow-duplication.yml` and `deploy-drift.yml` are not affected; Codex.)
- `github.event.before` as base: loses commits of cancelled runs (Codex).
- Inline shell copy in each YAML: untestable, which is the gap asked to close.
- bats: not installed in these repos' CI; pytest already is.
- Changing AIFactory to the script: no behaviour gap for squash merges; churn.

## Risks

- A non-matching `kustomization.yaml` layout yields an empty base and falls
  back to HEAD: coverage shrinks, deploy unaffected.
- `fetch-depth: 0` adds checkout cost. The builds use `context: .` but every
  `.dockerignore` excludes `.git`, so images are unchanged.
- Commit bodies are untrusted: slugs are regex-validated, printed through
  printf, and never expanded by the shell.
- Multi-slug bumps are counted per association by `governance_cli` (follow-up).

## Verification

- `pytest tests/test_plan_slug_trailers.py` in each repo, plus `shellcheck`
  on the script when available.
- Dry-run of the bump message build against a temp repo, pasted in each PR.
- `yamllint`/`python -c yaml.safe_load` of the edited deploy.yml; repo drift
  and duplication checks stay green on the PR.
- After merge and the next deploy, the factory-gitops bump commit shows the
  trailer (owner-observable; commented on Factory#1958).
