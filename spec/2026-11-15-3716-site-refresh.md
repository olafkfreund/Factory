# Spec: refresh the five Factory GitHub Pages sites

## Design

### Source of truth: one facts sheet per product

Each claim on a refreshed page comes from a facts sheet built from release
notes, merged PRs and source on `main` (2026-11-15). Each sheet separates
"shipped" (released or on `main`) from "in progress (dev only)" and flags
shadow/warn/off-by-default features. The sheets are committed with this task
under `spec/2026-11-15-3716-site-refresh/` so the PR reviewer can check
every claim:

| Sheet | Shipped state | Notable corrections it proves |
| ----- | ------------- | ----------------------------- |
| `AIFactory-facts.md` | v3.10.16 (2026-10-31); dev 33 commits ahead | 8 themes; license is "MIT OR GPL-3.0" per the site footer, not open-core |
| `PFactory-facts.md` | v0.6.42 (2026-10-31); dev 9 ahead | 7 review lenses in code (`plan/review/lenses/base.py:71-89`); no single "stage count" exists |
| `TFactory-facts.md` | v0.9.49 (2026-10-31); dev 11 ahead | lanes: Python, TypeScript, Java, Kotlin; 503 test files; agent count and signal count are not provable |
| `CFactory-facts.md` | `main` at #509 (2026-10-30); no releases | 10 cockpit views; stalled stages flagged after 900 s, deleted after 24 h; running stages never pruned |
| `Factory-facts.md` | `main` | RFC table with statuses; roadmap items now done; open epics #310 (#312, #314, #324), #1958, #389, #392 |

A number that the sheet cannot prove does not appear on a site.

### HTTPS

factory.freundcloud.com and cfactory.freundcloud.com have
`https_enforced: false`. Turn it on (`gh api -X PUT
repos/olafkfreund/<repo>/pages -F https_enforced=true`), as the other three

### Numbers

Every number on a site (stat grids, tool counts, release counts, test
files) is recounted when the page is written, and the PR lists each number
with the command that produced it. A number that cannot be reproduced is
dropped.

### Going live

- Factory: one PR to `main`.
- AIFactory, PFactory, TFactory, CFactory: one PR to `dev`, then one
  `sync/dev-to-main-<n>` PR to `main`. That PR is a branch from `main` with
  `git checkout origin/dev -- <the docs files this task changed>`: only
  those files, no code. This avoids cherry-pick conflicts where `main`'s
  docs lag `dev` (CFactory). The reviewer checks that the sync diff carries
  no dev-only feature described as shipped. `deploy.yml` ignores `docs/**`,
  so nothing redeploys. AIFactory's `docs.yml` publishes `gh-pages`.

## Alternatives rejected

- **Promote `dev` → `main` or cut releases to publish docs:** ships 9–33
  unreleased code commits per repo and redeploys the clusters for a docs
  change.
- **Edit the RFC status lines that contradict merged work** (RFC-0019,
  0020, 0021, the 0019 spike): an RFC's status is the design owner's call.
  The index shows the RFC's own words. A follow-up issue lists the
  contradictions with evidence.
- **Hand-written RFC table:** misses new RFCs.
- **Reading the status out of each RFC's body with Liquid:** unreliable on
  Pages' Jekyll 3.10 (content may already be HTML; RFC-0001's status contains
  `·`). Codex review, 2026-11-15.
- **Cherry-picking the `dev` docs commit onto `main`:** conflicts where
  `main`'s docs lag `dev`.
- **Version string kept in `_config.yml`, bumped by the release workflow:**
  a workflow change outside `docs/`, for a label that a "latest release" link
  covers.
- **New screenshots:** needs cluster access the intent rules out.
- **Redesigned homepages:** outside the intent; layouts stay.

## Risks

- **Over-claiming:** a theme taken from a release note may be flag-gated or
  in shadow mode. The sheets mark these; posts must keep the marking.
  Review checks each post against its sheet.
- **`onBrokenLinks: 'throw'` fails the AIFactory docs build** on a link this
  task misses. That is intended: fix it in the same PR. The build runs on
  the `dev` PR before anything reaches `main`.
- **RFC `status:` drift:** the front-matter short form and the body line
  are two copies. A later RFC edit can update one and not the other. The
  short form only copies; #3717 handles the current contradictions.
- **Synced file carries other `dev` edits:** a docs file this task touches
  may already hold `dev`-only edits from other PRs. They go live with the
  sync; the reviewer reads the sync diff against `main` for dev-only claims.
- **Pages build differs from local builds:** verification uses GitHub's
  Pages builder (the `jekyll-build-pages` image, or the locally installed
  `github-pages` 232 / Jekyll 3.10 gems), the same versions Pages runs.
- **`branch-divergence.yml` watchdog:** it fails when a commit on `main` has
  no equivalent on `dev` and the touched files still differ. The sync PR
  copies `dev`'s exact file contents, so the files match; Verification 8
  runs the check.
- **CFactory's PFactory port:** `architecture.md` says 3105, which is
  CFactory's own code default (`config.py:65`). It stays; changing the page
  would make it contradict the code.
