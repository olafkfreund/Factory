# Spec: hub-owned shared shell

## Design

### Files: hub `shared/factory-ui/`

- **`shell.css`:**
  - plain CSS; tokens only (`var(--f-*)`); no Tailwind;
  - BEM-style `f-` prefix: `f-shell`, `f-topbar`, `f-strip`, `f-side`,
    `f-page`, `f-state`;
  - a 12px text floor.
- **`AppShell.tsx`:** React with no other dependencies; a prop-driven layout.
- **`ProjectSwitcher.tsx`:** the breadcrumb combobox (search, recents,
  "Add project").
- **`PipelineStrip.tsx`:** a compact strip generalised from CFactory's
  `PipelineStrip.tsx` and its `.pstrip` CSS (`index.css` lines 1413–1470).
- **`TaskCard.tsx`:** the shared work card (see the work cards section below).
- **`PortalSwitcher.tsx`:** stays.
- **`CommandPalette.tsx`:** stays.

### Layout

```
┌ f-topbar 48px ──────────────────────────────────────────────────────────────┐
│ [logo] Plan·Build·Test·Cockpit·Meet │ Project ▾ / View │ … │ theme search ⚑N v · user │
├ f-strip 64px (optional per page) ───────────────────────────────────────────┤
│ (◎ PLAN 2 ·37 failed) ─── (◎ CODE 4) ─── (◎ TEST 0 ·8 failed)     [clear filter] │
├ f-side 240px ┬ f-page ──────────────────────────────────────────────────────┤
│ nav items    │ f-page-head: title (20/28) + one-line description + actions  │
│ …            │ content                                                      │
│ ── Project   │                                                              │
│    Settings  │                                                              │
│ [+ primary]  │                                                              │
└──────────────┴──────────────────────────────────────────────────────────────┘
```

**Top bar (48px),** modelled on CFactory's `.topbar`:
- *Left:* the portal wordmark. Logo plus name only; Archivo for the
  wordmark only.
- *Centre-left:* `PortalSwitcher` (five entries), then `ProjectSwitcher`
  as breadcrumb segment 1, then the current view name as segment 2.
- *Right:*
  - a theme segmented control (Light, Dark, System);
  - search / command palette (⌘K);
  - the Needs-you count;
  - live / version;
  - the user menu (Preferences, Log out).

**Pipeline strip (64px):**
- the portal passes its stages: `{key, label, service, count, failed, href}`;
- each stage is a 36px ring with the count and a failure badge that links to
  the filtered view;
- shown on overview pages and omitted on settings pages.

It replaces:
- the AIFactory, PFactory and TFactory 240px `pl-railpanel`;
- AIFactory's Kanban rail;
- the CFactory strip, which becomes the hub strip.

Each portal's own stages:

| Portal | Stages |
|---|---|
| PFactory | Ingest, Plan, Review, Approved |
| AIFactory | Plan, Code, QA, Review |
| TFactory | Plan, Generate, Execute, Report |
| CFactory | Plan, Code, Test |

**Sidebar (240px):**
- collapses to a 48px rail, and below 900px becomes a drawer;
- holds the portal's own nav items, an optional badge each;
- Project Settings is pinned at the bottom, then the portal's primary action
  (for example "+ Task");
- there is no project picker in the sidebar.

**Page head:**
- the title is 20/28;
- one line of description;
- a right-aligned action slot.

**State components:** `f-state--empty`, `--loading` and `--error`:
- *empty:* one line plus one action;
- *loading:* a skeleton on first load only;
- *error:* inline, with the reason, recovery and an error id.

### Work cards: `TaskCard.tsx`, with the `f-card` styles in `shell.css`

This is the owner's request of 2026-11-23: smaller, collapsed task boxes.
Today a TFactory card is about 175px tall:
- the name;
- a UUID line;
- two badges;
- the age;
- a 4-link phase row (Plan, Generate, Execute, Report);
- a floating icon pill.

Five finished runs fill the whole column.

| State | Shape |
|---|---|
| **Collapsed** (default for done, triaged and dismissed) | One 36px row: status dot and icon, the name (truncated, full name on hover), one status badge, the age, and a chevron. No UUID, no phase row, no buttons. |
| **Active** (running, queued, needs you) | About 72px: the name; one status badge plus a 2px progress line; the age; one primary action at most. |
| **Failed** | The active shape, plus a 3px danger bar on the left, one line of reason, and Re-run / Dismiss as small outline/ghost buttons. |
| **Expanded** (click the chevron or the row) | Expands in place to show the id (copyable), every badge, the phase links (Plan, Generate, Execute, Report) and the portal's actions. Only one card is expanded at a time. The open card is remembered per project in `localStorage`, as a convenience only. |

Layout and behaviour rules:
- **A column with more than 8 collapsed rows** shows the first 8 and a
  "Show N more" link.
- **Column headers** show the count, so empty columns stay one line
  ("Nothing planned"), not a tall box.
- **The board** keeps its columns, but they size to their content instead
  of stretching to the window height.
- **Props:**
  ```
  {title, id, status, tone: neutral|running|success|warning|danger, age,
   reason?, progress?, badges?, links?, actions?, collapsedByDefault?,
   expanded?, onToggle?}
  ```
- **Every portal's work items use it:**
  - TFactory spec cards;
  - AIFactory Kanban task cards;
  - PFactory plan cards;
  - CFactory planning and pipeline cards.

  This replaces their own card components (B14 and B15 get their final look
  here).

### Settings

- Project Settings becomes the routed page `/p/<slug>/settings`, with tabs
  General, Git, Memory and MCP.
- Preferences becomes a page reached from the user menu.
- The mixed settings modal is removed per portal during adoption.

### Deleted in each portal (during adoption)

- `ProjectTabBar.tsx` and `SortableProjectTab.tsx`;
- the sidebar project selector;
- the per-portal top bar and rail panel;
- PFactory's ambient, flying-document and sticker CSS;
- CFactory's own `.topbar`, `.sidebar` and `.pstrip` CSS.

### Gates

- The drift gate adds `shell.css`, `AppShell.tsx`, `ProjectSwitcher.tsx` and
  `PipelineStrip.tsx` to the canonical set:
  - React portals vendor them to `src/components/factory-ui/`, and
    `shell.css` to `src/styles/`;
  - CFactory vendors the same;
  - RFactory vendors only `shell.css` (and `tokens.css`).
- The contrast and small-text gates apply to `shell.css`.

### RFactory

RFactory keeps its plain JS:
- it vendors `tokens.css` and `shell.css` into `web/public/`;
- it renders the same top-bar markup (`f-topbar` classes) in its HTML;
- it has no sidebar or strip, because it has no pipeline.

## Alternatives rejected

| Alternative | Why rejected |
|---|---|
| Restyle each portal's own shell (the original C2.6) | Five copies drift again |
| A shared npm package | No registry and no build in the hub; byte-exact vendoring is the established pattern (verification-core, factory-ui) |
| A Tailwind-based shell | CFactory and RFactory don't use Tailwind |
| Keeping the project tab row | Two project switchers; the owner wants the CFactory model |

## Risks

- **Large UI change per portal.** Mitigation: one portal at a time, a browser
  test at two widths, and the owner side-by-side at TFactory.
- **Capabilities hidden in the old shell.** Examples: the tab bar's per-project
  context menu, and drag-reordering tabs (dropped by design; recents replace
  it). Mitigation: an inventory per portal before deleting.
- **A drift-gate pin bump per portal.** Coordinate with C2 step 1 (#1665).

## Verification

- Hub: a unit test of `AppShell` rendering (vitest is not in the hub; a
  render snapshot test lives in the first adopting portal); the drift,
  contrast and small-text gates pass.
- Per portal:
  - typecheck, tests, lint and build;
  - an inventory check that every old shell action is reachable;
  - a browser test at 1280px and 390px in light and dark, recorded as a GIF;
  - content starts at no more than 140px on overview pages;
  - five finished runs take at most 200px (5 × 36px rows plus gaps).

### R3. `AppShell` is presentation; portals keep behaviour

The props contract (supersedes the sketch):

**Navigation**
- `nav` items: `{id, label, icon, badge?, disabled?, external?: {href}}`.
- `activeNav`.
- `onNavigate(id)`: client-side; the shell never renders a reloading
  `<a href>` for internal views.

**Project**
- `projects`, `currentProject?`, `onSelectProject(slug)`,
  `onAllProjects?()`, `onAddProject?()`.
- `projectSubtitle?`: the repo label or path.
- `projectSettings?: {active, onOpen}`: pinned at the bottom of the
  sidebar.
- `primaryAction?: {label, onClick, disabled?, busy?, disabledReason?}`.

**Pipeline strip**
- `strip?`: `{stages: PipelineStage[], activeStage?, onSelectStage(key|null),
  onSelectFailed?(key), alarm?: key}`.
- `PipelineStage` is `{key, label, service, count, failed, tone}`.
- This is CFactory's interactive behaviour, made generic:
  - clicking a stage toggles that stage's filter;
  - the failure badge has its own handler;
  - clear-filter;
  - a flare on new failures, with reduced-motion respected.
- The strip shows on every view except settings pages.

**Slots** (`ReactNode`), so per-portal status keeps a home:
- `topbarStatus`: AIFactory, PFactory and TFactory pass the Claude / CLI /
  OpenAI status badges and the `RateLimitIndicator`; CFactory passes the
  live/offline dot, `BackendPill` and Refresh.
- `sidebarHeader`: project setup prompts, for example "Initialize to create
  tasks".
- `sidebarFooter`.

**Chrome**
- `sidebarCollapsed` and `onSidebarCollapsedChange`, controlled by the
  portal.
- `user?: {name, menu: {id,label,onSelect}[]}`: Preferences, Help & docs,
  Log out. The portal keeps its logout-confirm dialog.
- `theme` and `onTheme`.
- `needsYou?: {count, onOpen}`.
- `version?`.
- `labels`: every built-in string, so the portal can pass `t(...)` values.

**Shortcuts**
- `AppShell` binds no global shortcuts.
- The portal keeps its ⌘K handler and passes `onSearch`.
- The bare `/` shortcut is dropped (it would collide with Monaco and
  xterm).

**Kept in the portal adapters:**
- route parsing and slug→id resolution;
- store sync and auth guards;
- the Git setup and Initialize dialogs, and the provider-driven nav items;
- kept-mounted terminals.

**Old shell actions with a new home:**

| Old action | New home |
|---|---|
| Tab close, ⌘1–9, ⌘Tab, ⌘W | `ProjectSwitcher` recents, ⌘1–9 bound by the portal |
| Help & docs | user menu |
| All projects | `ProjectSwitcher` "All projects" (`onAllProjects`) |
| Project path | `projectSubtitle` |
| CFactory "clear project scope" | `onAllProjects` |
| CFactory Observe | an `external` nav item |
| CFactory Refresh | `topbarStatus` |
| Drag-reordering tabs | dropped by design |

### R4. `WorkCard` is a presentation shell; adapters keep controls

**Props**
- **Identity and content:** `{title, subtitle?, status, tone, age,
  reason?, progress?, phases?: {key,label,state:'done'|'active'|'failed'|'pending'}[],
  badges?}`.
- **Open vs expand:** `onOpen?` opens the detail and is separate from
  expand. `expanded` and `onToggle` belong to the chevron button only, so
  drag and sortable wrappers don't conflict.
- **Actions:** `actions?: {id,label,onClick,variant,disabled?,busy?}[]`.
- **Expanded content:** `children` is the portal-supplied content when
  expanded (comments, acceptance criteria and so on).
- `collapsedByDefault?`.
- **Performance:** cards are memoised and compare only displayed props.

**`WorkColumn`:**
- owns "show the first 8 collapsed, then Show N more" and
  single-expanded-at-a-time;
- the expanded id is remembered per project in `localStorage`, keyed by
  project id plus item id (fleet views include the project).

**Scope**
- TFactory spec cards, AIFactory `PipelineBoard` and `KanbanBoard` cards
  (inside the existing sortable wrappers), PFactory `PlanBoard` cards and
  CFactory **Pipeline** board cards use `WorkCard`.
- **Exempt for now:** CFactory Planning and Backlog `CardBody`. These are
  inline-editable, with a status select, priority, stage dispatch and
  comments. They get only the shared `f-card` styles; a later issue decides
  whether to adopt the component.
- CFactory Done cards keep their status select (reopen).

**Per-portal stage mapping**
- PFactory's strip uses its real three buckets: Backlog (including
  processing), Review and Approved.
- The other portals' strips use the stages their boards already compute.
