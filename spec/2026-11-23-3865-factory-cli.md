# Spec: one `factory` CLI and MCP front door (release 1)

Release 1 only: CLI + MCP over each portal's existing scoped key. Fleet login
is a separate intent (see intent, open question 2).

All file references are `origin/dev` (products) or `origin/main` (Factory)
as of 2026-11-23.

## Design

### D1. Package: `shared/factory-cli` (Factory repo)

- Python ≥ 3.11 package `factory_cli` with a `pyproject.toml` (first
  installable package under `shared/`; the others stay sys.path modules).
  Entry point `factory = factory_cli.__main__:main`.
- Runtime deps: stdlib `urllib` for HTTP (same as PFactory's
  `plan/emit/http_transport.py`), `pyyaml` (frontmatter), `mcp` (the SDK the
  portal stdio servers already use, `AIFactory mcp_server/aifactory_server.py:132`)
  imported only by `factory mcp`.
- Reuses `shared/factory-common` (`assert_safe_outbound_url`, `redact`,
  `sanitize_log`) by vendoring the module into the package at build time
  (same as `factory-ui` is vendored), not by sys.path.
- `flake.nix` gains `packages.<system>.factory-cli` (buildPythonApplication)
  and `apps.<system>.factory`; today it exposes only `devShells` (`:20`).
  Non-NixOS hosts: `uv tool install ./shared/factory-cli`.

### D2. Configuration and credentials

- Per portal `p ∈ {pfactory, aifactory, tfactory, cfactory}`:
  URL from `<P>_API_URL` (else `~/.config/factory/config.toml` `[portals.<p>] url`);
  key in the stdio clients' order (`*/agents/tools_pkg/http_client.py:16-26`):
  `$<P>_MCP_KEY` → `~/.<p>/.mcp-key` → `$<P>_API_TOKEN_FILE` → `~/.<p>/.token`.
  CFactory adds `$CFACTORY_API_KEY` / `~/.cfactory/.mcp-key`.
- The config file holds URLs only. Keys are read at call time, never logged;
  error bodies go through `redact()`. Outbound URLs pass
  `assert_safe_outbound_url` (https, or http on loopback).
- `factory doctor` prints, per portal: URL, which key source was found (name
  only), `GET /api/health` version, and whether the key authenticates.

### D3. `factory submit` — approved artifacts in, signed contract out

Client side (`factory submit <slug|path>` in a git worktree):

1. Resolve `intent/<slug>.md`, `spec/<slug>.md`, `plan/<slug>.md`; all three
   must exist and have frontmatter `status: approved`, else exit 2 naming the
   file.
2. For each file: path, git blob SHA of the committed content
   (`git rev-parse HEAD:<path>`; refuse if the working copy differs from
   HEAD), and the approving commit — the latest commit whose subject matches
   `docs(<stage>): approve <slug>` — with its SHA and author. Missing approve
   commit → exit 2.
3. Repo identity: `origin` remote normalized to `owner/repo` (+ provider),
   current branch, HEAD SHA, base ref (`--base`, default the repo default
   branch).
4. Call PFactory (below); then `approve`; then `emit-contract` with
   `dry_run=false`. Print the PFactory session id, the correlation key, the
   AIFactory task/spec id from `contract_result`, and exit 0 only when
   `contract_result.ok` is true.
5. Outcomes: 4xx → print the portal's `detail` (redacted), exit 1; timeout or
   5xx after the emit request was sent → "outcome unknown", print the session
   id and correlation key, exit 3. Never retries the emit itself; a re-run
   with the same artifacts is idempotent (D4 dedupe).
6. `--dry-run` stops after a dry-run emit and prints the contract summary.

PFactory side (new, additive):

- Module `apps/backend/plan/ingest/artifacts.py`, modelled on
  `plan/ingest/speckit.py:342` (`ingest_speckit`): maps the three files to
  `(NormalizedPlan, EpicPlan)`:
  - `NormalizedPlan`: title from the intent H1, description from intent
    Problem + Proposed outcome, acceptance criteria from the spec
    Verification section (one per bullet), `source_format="factory-artifacts"`.
  - `EpicPlan`: one `ChildIssue` per numbered item under the plan's
    `## Steps`, in order, `depends_on` the previous step; body = the step
    text including its verify/Traps lines; the full plan text folded into
    `epic_body` (as speckit does with `plan.md`).
  - A plan with no parseable steps is rejected (422), never decomposed.
- Route `POST /api/mcp-stdio/plan/sessions/ingest-approved` (scope
  `plan:write`, same `_PlanWrite` dependency as `ingest-text`,
  `mcp_stdio/router.py:380,412`). Body (`extra=forbid`): `slug`, `repo`,
  `base_ref`, `branch`, `head_sha`, and `artifacts: [{stage, path, content,
  blob_sha, approve_commit_sha, approve_commit_author}]` (exactly one per
  stage).
  - Server recomputes each blob SHA from `content` and rejects a mismatch.
  - Runs the existing intake injection scan and readiness gates
    (`_detect_and_plan_type` scan part and `run_gates`, `service.py`), not
    `_decompose` or `synthesize`.
  - Stores `session.source_artifacts` (new optional field on `PlanSession`)
    and sets `session.epic` directly; status `processed`.
  - Dedupe key `(repo, slug, plan blob_sha)`: a repeat returns the existing
    session (200, same id) instead of creating a second one.
- Approval: the CLI then calls the existing
  `POST /api/mcp-stdio/plan/sessions/{id}/approve`. The approving identity is
  the authenticated user key (`auth_kind == "user"`), which the existing
  `require_user_approval` check in `_emit_contract` (`service.py:3006-3030`)
  already demands for a live emit. No new approval kind.
- Contract: `assemble_contract` (`plan/emit/contract_emit.py`) adds, when
  `session.source_artifacts` is set,
  `provenance.source_artifacts` (list of `{stage, path, blob_sha,
  approve_commit_sha, approve_commit_author}`) and
  `provenance.human_approval` (`{approved_by, auth_kind, approved_at,
  plan_hash}` from `review.human_approval`). `provenance` is already the
  extension bag (`task-contract.schema.json:19`, `additionalProperties:
  true`), and the HMAC covers the whole body except `approval`
  (`signing.py:53-75`), so both are signed. The signing envelope's
  `approval.approved_by` stays `"pfactory"`.
- The emit path for these sessions forces `PFACTORY_EMIT_FALLBACK` off: a
  failed fast path returns the error, never a create-and-run
  (`contract_emit.py:435`).

Factory side:

- `apis/task-contract.schema.json`: declare `provenance.source_artifacts`
  and `provenance.human_approval` as optional typed properties (still
  `additionalProperties: true`), regenerate `shared/factory-contracts`
  (`scripts/gen_contracts.py`), and sync PFactory's copy
  (`apps/backend/plan/emit/contracts/task-contract.schema.json`).

AIFactory side: no code change required — `from-plan` keeps unknown signed
fields and stores the contract verbatim (`trusted_plan.py:903,918`). Add one
test that a contract carrying both provenance fields verifies and is stored.

### D4. `factory test`

`factory test --repo OWNER/REPO --branch B [--pr N] (--spec SLUG | --criteria FILE) [--project ID]`

- Project: `--project`, else match the normalized repo against
  `GET /api/projects` on TFactory (only projects the key can see). Zero
  matches → "project not found" (same wording as the portal's 404, D6);
  more than one → exit 2 asking for `--project`.
- Criteria: `--spec SLUG` sends `spec/<slug>.md`; `--criteria FILE` sends that
  file. No criteria → exit 2.
- Calls `POST /api/specs/ingest` (`TFactory routes/specs.py:248`) with
  `project_id`, `spec_id` (`<slug>` or `cli-<branch>-<short sha>`),
  `spec_text`, `source_branch`, `repo`; with `--pr`, then
  `POST /api/specs/{project_id}/{spec_id}/pr` (`:347`).
- Prints `task_id` as `project_id:spec_id` (the form
  `GET /api/tasks/{task_id}` needs, `tasks.py:1132-1140`) and
  `planner_scheduled`; warns when it is false (`TFACTORY_AUTO_PLAN` off).

### D5. `factory status`

`factory status <id>` accepts a correlation key, `pf:<session>` or
`af:<task>`, or `tf:<project:spec>`.

- PFactory session → `GET /api/mcp-stdio/plan/sessions/{id}` (status,
  `contract_result`, correlation key).
- AIFactory task id (from `contract_result`) → its task status route.
- TFactory → `GET /api/tasks/{project:spec}` when known.
- Correlation key with a CFactory key configured →
  `GET /api/workitems/{key}` (`CFactory routes_workitems.py:149`) for the
  joined view; otherwise the per-portal calls above.
- Any 404 prints "not found" with no portal-specific detail.

### D6. `factory mcp` and `factory mcp-config`

- `factory mcp`: stdio MCP server exposing `factory_submit`,
  `factory_test`, `factory_status`, `factory_doctor` — same functions as the
  CLI, same arguments, JSON results. `factory_submit` defaults to
  `dry_run=true`; a live submit needs `dry_run=false` explicitly (mirrors
  `plan_emit`).
- `factory mcp-config claude|codex|agy` prints the entry for that agent's
  format (Claude `.mcp.json` JSON, Codex TOML `[mcp_servers.factory]`, agy
  `~/.gemini/.../mcp_config.json` JSON), command `factory mcp`, no keys or
  env secrets. `--write` merges it into the user's file, adding the
  `factory` entry only, and refuses if a `factory` entry exists without
  `--force`.

## Alternatives rejected

- **Four calls from the CLI over the existing routes, keeping
  `plan_process`:** re-decomposes the approved plan, which the intent rules
  out.
- **Pre-built epic passed into the generic `ingest-text`:** `IngestTextBody`
  is `extra=forbid` and every caller would gain a way to skip decomposition;
  a dedicated route keeps the rule narrow and testable.
- **A new `approval` kind for git commits:** the user-key approval already
  gates live emits; git approval commits are recorded as provenance, signed,
  not trusted as authorization on their own.
- **Overloading `approval.approved_by`:** it names the signing authority in
  the HMAC envelope that AIFactory's keyring checks; changing it breaks
  verification.
- **Go binary:** no shared code with the Python portals and contracts;
  revisit only if non-Python hosts need it.
- **Generating per-portal MCP entries instead of one `factory` server:** keeps
  four credentials in agent configs, which the intent removes.

## Risks

- PFactory's parser for `## Steps` is new: a malformed plan yields wrong
  children. Mitigation: reject unparseable plans, unit tests on this repo's
  real plans, `--dry-run` shows the children before a live emit.
- Low/medium-tier sessions: `_emit_contract`'s user-approval check only runs
  when `require_user_approval` is set; the new route's emit sets it always.
- TFactory project match by repo can be ambiguous across forks; handled by
  the explicit `--project` exit.
- `mcp` SDK version drift between the portals and the CLI; pin a range in
  `pyproject.toml`.
- `--write` edits a user config file; it touches only the `factory` key and
  keeps a `.bak`.

## Verification

- Unit (Factory): artifact resolution and approve-commit detection on a temp
  git repo; key lookup order; redaction of error bodies; `mcp-config` output
  for all three agents contains no secrets.
- Unit (PFactory): `ingest/artifacts.py` on this repo's `intent/spec/plan`
  triples; route rejects blob mismatch, missing stage, unparseable steps;
  dedupe returns the same session; contract carries signed
  `provenance.source_artifacts` and `provenance.human_approval`; emit with
  `PFACTORY_EMIT_FALLBACK=1` still does not fall back for these sessions.
- Unit (AIFactory): from-plan accepts and stores a contract with the new
  provenance fields.
- Schema: `task-contract.schema.json` validates a contract with and without
  the fields; regenerated contracts package matches.
- Live acceptance (after PFactory release): from a clean Claude Code, Codex
  and agy session, `factory submit` this issue's own artifacts against
  `aifactory-demo` with `--dry-run`, then live; AIFactory shows a task with
  no planning phase and the stored contract carries the provenance;
  `factory status` shows PFactory and AIFactory state; `factory test`
  schedules a TFactory run; a key without access to the project gets the
  same "not found" as an unknown project.
