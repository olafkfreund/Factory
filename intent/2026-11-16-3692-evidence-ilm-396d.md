# Intent: Evidence ILM keeps 396 days, not 90

## Problem

Risk R-006 asks for a 13-month evidence floor. No ILM rule has it. In factory-gitops
`apps/minio/manifests/manifests.yaml:335-361`, `evidence-90d` expires `factory-evidence`
objects after 90 days and `evidence-{pfactory,aifactory,tfactory}-90d` do the same for
`role=evidence` objects in `factory-artifacts`. The bucket Job's read-back checks only that
the rule IDs exist, so a wrong day count would pass unnoticed. SoA A.5.33 and A.8.10 and SOC 2
CC6.5 and C1.2 carry the gap.

## Proposed outcome

- Every evidence expiry rule is at least 396 days (13 months); rule IDs no longer say `90d`.
- The Job fails if an exported rule has the wrong day count, not only a missing ID.
- Storage headroom for the longer retention is measured and recorded.
- R-006, SoA A.5.33 / A.8.10 and SOC 2 CC6.5 / C1.2 state the new measured value.

## Affected users and systems

MinIO on the k3d-factory cluster (`factory-evidence`, `factory-artifacts`), the
`minio-create-bucket` Job, the evidence-collector docs, compliance records (Factory `docs/compliance`).

## Constraints

- Log (30d) and backup (14d) rules stay unchanged.
- ILM expiry only deletes objects from import time on; raising days never resurrects purged objects.
- No live-cluster writes: ArgoCD applies the gitops change after merge.

## Open questions

None. Whether to go beyond 396 (e.g. 365-day SOC 2 audit window plus margin) is not asked; 396 is the register's floor.
