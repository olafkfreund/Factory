# Intent: prove the Factory suite works end to end, through every surface and model

## Problem

Each factory has its own unit tests and the hub has seam checks (`scripts/parr_regression.py`), but nothing proves the whole journey works together:

1. create a GitHub repo and onboard it;
2. plan, then review the plan;
3. code, then review the code;
4. PR and merge;
5. TFactory test, then review the result.

Nothing proves it across the three ways people and agents drive the suite (MCP, the `factory` CLI and the portal UI), or across the models the agents run on. Cost per model is not measured against an outcome. Whether agents follow the rules (CLAUDE.md, artifact workflow) and use their skills is not checked from evidence. RFactory, the meeting bot that reads CFactory, has no live integration test.

Owner, 2026-11-24: "We need to test everything twice and verify that it all works together … include RFactory … use multiple models, test the cost, test management using MCP, cli and portal UI and review how we use agents and rules and skills."

## Proposed outcome

A repeatable test campaign, run by the factories' own agents, that:

- **Drives several fixture projects** through all five stages on prod, through MCP, the CLI and the UI.
- **Runs the matrix on three models:** Claude, Codex and Gemini via agy.
- **Counts every journey twice,** in three senses:
  - a repeat run;
  - read-back on a different surface;
  - an independent hidden acceptance suite after the TFactory verdict.
- **Reports cost per accepted build** for each model, reconciled across three sources.
- **Proves that the gates stop bad work:**
  - a trap project must not go green;
  - a planted bug must be caught;
  - a tampered plan must be rejected.
- **Audits rule and skill use** from git history and transcripts.
- **Covers RFactory's** auth, standup and review against the test cards.
- **Leaves nothing behind:** every test repo, project and card is cleaned up by a guarded sweeper.

## Affected users and systems

- **The owner:** reads a campaign summary and decides on disagreements only.
- **Prod services:** AIFactory, PFactory, TFactory and CFactory on k3d (p620), plus RFactory.
- **GitHub:** the Freundcloud org holds the test repos.
- **Keycloak:** a test user.
- **Code:**
  - the Factory hub: `scripts/`, `tests/e2e/`, workflows;
  - `shared/factory-cli`, which gains parity verbs.

## Constraints

- **Repos:** test repos only in **Freundcloud**, named `e2e-<yyyymmdd>-<P#>-<run>` with the topic `factory-e2e`. The harness refuses anything else, and the sweeper deletes only matching repos.
- **Target:** prod, under a dedicated test tenant/project, and never the owner's own identity or keys. Post on the agent bus before prod test traffic.
- **Budget:** $450 metered per campaign. Each run is capped at $15 or 60 minutes. Subscription usage is reported as tokens, never as invented dollars.
- **Models:** Claude, Codex and Gemini (agy). Ollama is out of scope.
- **Secrets:** they live in agenix and CI secrets only, and evidence passes gitleaks before upload. The owner creates the test user and the scoped GitHub token. Claude never sees the values.
- **Roles:** Codex and agy implement, Claude leads and merges, and Fable reviews oracles and audits rules. The reviewer of a stage is never the model that built it.
