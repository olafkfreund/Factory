# Intent: security-alerts CronJob fails every run (OpenObserve HTTP 400)

## Problem

The `factory/security-alerts` CronJob (factory-gitops `apps/security-alerts`, Factory#3688) has failed
every run since it was deployed. Its logs read `auth_failure_spike: OpenObserve HTTP 400`,
`auth_failure_spike: error n=None`, `egress_anomaly: not_configured n=None`. Read-only queries against
OpenObserve show the cause: the query `... FROM "audit_chain" WHERE action = 'auth.failure'` is
answered `{"code":20004,"message":"Search field not found: Schema error: No field named action ..."}`.
OpenObserve builds a stream's schema from the data it has seen; no row with an `action` field has ever
reached `audit_chain` (the CFactory chain forwarded there carries `kind`), so the column does not exist and
the query is rejected instead of counting zero. job-watchdog then raises Factory#3758.

## Proposed outcome

The CronJob exits 0 while no auth-failure row exists, records that state visibly in `job_health`
(not as `ok`), and still exits 1 and fires normally for a real error and once rows appear. An unconfigured
egress source does not fail the Job (it already does not: `not_configured` leaves the exit code at 0; this
is now pinned by a test). Any other query error still fails loudly.

## Affected users and systems

factory-gitops `apps/security-alerts/manifests/alerts.py`, `test_alerts.py`, `docs/security-alerts.md`;
job-watchdog issue Factory#3758; the owner's alerting on auth failures (Factory#3688, #3732).

## Constraints

Must: never print a value, a response body or `str(exception)`. A 400 that is not the missing-field
error must stay an `error` and exit 1. The missing-stream (404) behaviour is unchanged. No live-cluster
change. Must not: change the egress source (owner decision, Factory#3688).

## Open questions

None. Known limit, for the owner: whether AIFactory `auth.failure` events reach `audit_chain` at all
is an ingest question outside this fix; the new `no_field` status makes it visible in `job_health`.
