# Intent: Plan-Slug trailer on the PFactory, TFactory and CFactory gitops bump

Issues: olafkfreund/Factory#1958 (epic, acceptance item 3, gap d),
olafkfreund/PFactory#1079, olafkfreund/TFactory#1568, olafkfreund/CFactory#556.
Predecessor: olafkfreund/AIFactory#2109 / #2111 (AIFactory stamps the trailer).

## Problem

`python -m plan.governance_cli --repo <checkout>` joins a plan to the commits
carrying a `Plan-Slug: <correlation_key>` trailer (PFactory#1051). The
production change is the image bump commit in factory-gitops. AIFactory's
`deploy.yml` copies the trailer of the promoted commit into that bump commit
(`PLAN_SLUG`, git interpret-trailers, then `Plan-Slug:` in the body). The
PFactory, TFactory and CFactory deploy workflows author their bump with
`git commit -am "cd(<svc>): ${SHA} [skip ci]"` and no trailer, so for three of
four services the trail answers per plan, not per deploy.

Verified on origin/dev 2026-11-18: AIFactory deploy.yml lines 157-159 and
458-460; PFactory deploy.yml line 160, TFactory line 186, CFactory line 386.

## Proposed outcome

- Each of the three bump commits ends with one `Plan-Slug: <slug>` trailer per
  distinct slug found on the promoted commits (the pushed commit and the commits
  since the pinned SHA), deduplicated, validated with AIFactory's regex.
- The trailer logic is one script per repo, `scripts/plan_slug_trailers.sh`,
  covered by a test that builds a temp git repo, so CI proves it.
- AIFactory's existing step is checked with the same fixtures and any gap
  reported.
- Factory#1958 gets a status comment for Q12 gap d after merge.

## Affected users and systems

PFactory, TFactory, CFactory `deploy.yml` (bump step) and `scripts/`; the
factory-gitops history (commit bodies only, no manifest change); auditors using
`governance_cli --repo`.

## Constraints

- Reuse AIFactory's shell logic and its trailer format; no new format.
- Trailers must not break the bump: a missing or malformed trailer yields no
  trailer, never a failed deploy.
- Agent runs do not push to factory-gitops; only the workflows do, as today.
- The slug comes from commit messages (untrusted text): validate before use,
  pass through env, never interpolate into `run:`.
- PRs against dev; the coordinator merges.

## Open questions

None. Decision (owner delegation 2026-11-18): take the pushed commit plus any
distinct slugs between the SHA currently pinned in factory-gitops and HEAD,
deduplicated and capped at 10, as recommended in the task. The pinned SHA is
the base, not `github.event.before`, because the deploy workflows use
`cancel-in-progress`: a superseded run's commits would otherwise never be
linked (Codex review). Fall back to the HEAD commit alone when the base is
not in the checkout.

Out of scope, recorded (Codex review): `governance_cli.py` counts one commit
per slug association, so a bump naming two slugs counts twice; and `--repo`
also needs `--root <plan registry>`. Both are follow-ups on the PFactory side.
