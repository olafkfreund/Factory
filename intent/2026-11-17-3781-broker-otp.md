# Intent: Keycloak post-broker-login OTP challenge for GitHub-brokered users

## Problem

The `keycloak-mfa` job (factory-gitops#360) makes users enrol an authenticator, but a GitHub-brokered login is never asked for the code afterwards: Keycloak's brokered path has no OTP step unless a post-broker-login flow is bound to the identity provider. The `factory` realm is also configured by hand (`kcadm` snippets in `docs/keycloak-sso.md`), so there is no declarative record of the flow R-010 asks for. Two #360 items were never verified: the `requiredActions+=` array append on Keycloak 26.1, and what a brokered login does with a pending `CONFIGURE_TOTP`.

## Proposed outcome

- A committed, reviewable flow definition (realm-export format) for a conditional OTP step: users with an OTP credential are asked for a code on every brokered login; users without one are not blocked (enrolment stays the `keycloak-mfa` job's task).
- An idempotent job applies it, default off: `audit` (read-only), `install` (creates the flow, changes no login), `bind` (attaches it to the `github` IdP), `unbind`. Same shape as `keycloak-mfa`.
- The flow and both #360 questions are tested against a throwaway Keycloak 26.1 container, never the cluster.
- The owner is left one step: a login with a throwaway brokered GitHub account.

## Affected users and systems

Everyone who signs in through GitHub to AIFactory, PFactory, TFactory, CFactory; the `factory` realm of the in-cluster Keycloak; factory-gitops (new app, default `audit`). The `master` realm and its admin account are untouched.

## Constraints

- Never applied to the live realm by this work; no secrets handled; the credential is the existing `KEYCLOAK_ADMIN_PASSWORD` reference.
- Never edit or delete an existing flow; `master` realm recovery and break-glass accounts untouched.
- Default off: merging changes nothing until the owner edits the mode in git.
- The 01:48Z cluster disruption is owned elsewhere; no cluster action here.

## Open questions

None. Decision (owner delegation 2026-11-17): audit first, as for `keycloak-mfa`, because `bind` cannot lock out a user without an OTP credential and a lost authenticator is recoverable from the `master` realm.
