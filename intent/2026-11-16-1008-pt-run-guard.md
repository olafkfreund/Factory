# Intent: anti-loop guardrail and per-run token ceiling in PFactory and TFactory

One task, two code PRs: olafkfreund/PFactory#1008 and olafkfreund/TFactory#1510.
Follows AIFactory#2033 (PR #2051, merged), which added the same two controls there.

## Problem

PFactory and TFactory agent sessions have no effective stop. `max_turns` is a
hardcoded 1000 in `core/client.py`, neither repo has an anti-loop guardrail, and
nothing halts a run after it has used a set number of tokens. A stuck agent can
retry a failing call or burn tokens until a human notices.

## Proposed outcome

- With no environment variables set, an agent session that repeats the same
  failing tool call (or one tool failing many times) is stopped and the session
  returns an error naming the policy. An off switch restores the old behaviour.
- A per-run token ceiling (default on, 0 disables) halts the run. The halt
  reason is typed (`token_ceiling: ...`) and rides in the completion event
  `halt_reason` where that repo builds one.
- `max_turns` is configurable per repo; default stays 1000.
- Each repo's environment reference lists the three settings.

## Affected users and systems

PFactory (plan service, agent sessions) and TFactory (verify pipeline, agent
sessions), their completion events to CFactory, operators' env docs.

## Constraints

Must not break a run when a hook errors. Both controls switchable off. Env names
are per repo (`PFACTORY_*`, `TFACTORY_*`). No live-cluster change, no new
dependency. A usage count must come from where that repo already counts usage.

## Open questions

None. Default ceiling 10M tokens follows AIFactory (a judgement call).
