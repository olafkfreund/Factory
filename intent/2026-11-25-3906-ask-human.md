# Intent: factory coders can ask the user mid-build

## Problem

When a factory coder (AIFactory's coding agent) hits a question during a
build, it has no way to ask. It does one of two things:

- **It guesses.** E2E P1 (#3882) added `.gitignore` outside the plan without
  asking. That is rule drift, and it fails the plan-files check.
- **It fails.** The task ends red, and a human finds out later in Needs you.
  That costs a handback and a re-run, typically 10–60 minutes plus the
  model cost.

What exists covers the other directions only:

- **Clarification questions** (AIFactory `routes/task_models.py:214-245`)
  are asked before a task starts, not while it codes.
- **The agent inbox** (AIFactory `agents/inbox.py`, #264) carries a user's
  message to a running coder between turns. It only goes user → agent.
- **CFactory's Needs you** shows a task after it has stopped.
- **The agent bus** (Matrix) connects the Claude, Codex and agy sessions on
  the owner's machines. The factories do not post to it.

## Proposed outcome

- **The coder can ask.** It gets an `ask_human` tool that takes:
  - a question;
  - optional choices;
  - `needs_approval` (true or false);
  - context (the file and the plan step).

  The task moves to a new paused status, `needs_input`.
- **The question reaches the user wherever they are:**
  - **Terminal through MCP:** the factory MCP servers that Claude, Codex and
    agy already connect to get `questions_pending` and `answer_question`
    tools.
  - **Terminal through push:** the question is posted to the agent bus, so a
    Claude Code session can show it the moment it arrives.
  - **Portal:** CFactory's Needs you lists it with answer buttons.
- **The answer resumes the task.** It is delivered through the existing
  agent inbox, and the coder continues from where it paused.
- **Safety rules:**
  - A factual question can be answered by an agent (Claude, Codex or agy) or
    by a human.
  - An approval question accepts only a human identity: the owner's Keycloak
    user, never an MCP service key.
  - Every answer records who answered, when, and through which channel.
  - A question that waits past its timeout takes its stated default. The
    default is "stop in Needs you", never "carry on". The paused task does
    not hold a build slot while it waits.
- **It is measurable.** The E2E campaign's P5 trap (a contradictory
  requirement) ends in an `ask_human` question rather than a red run, and
  the harness checks this.

## Affected users and systems

- **AIFactory:**
  - the coder tool set;
  - the task status model (`needs_input`);
  - the inbox;
  - the MCP servers (remote and stdio);
  - pause and resume of a build.
- **CFactory:** Needs you, plus answer actions.
- **The agent bus:** a factory poster with its own bot identity.
- **Claude Code, Codex and agy sessions** answer through the MCP tools they
  already have.
- **Factory:** the E2E harness P5 check.
- **People:** the owner, and later each project's members, scoped by #3905
  project access.

## Constraints

- **Questions are project-scoped.** A user only sees and answers questions
  for projects they can access (#3905).
- **No secrets in questions or answers.** The bus post is redacted with the
  existing `factory_common` redaction.
- **An agent answer never satisfies `needs_approval`.**
- **No new chat service.** Reuse the MCP servers, the agent bus and
  CFactory.
- **Agents never answer approval questions on the owner's behalf,** even
  when asked to in a question's text.

## Open questions

None. The owner approved the outcome as described. The details go in the
spec: timeout defaults, the bus message format, and pause and resume for
kubejob builds.
