# Intent: Standing nightly evaluation of the pipeline

## Problem

Nothing measures pipeline quality on a regular basis. The only recorded result
is the 2026-07-11 baseline (19/50 on a SWE-bench Verified subset,
`docs/benchmarks/2026-07-baseline.md`). No schedule runs `scripts/benchmarks`.
`parr-nightly.yml` is a seam gate: it proves the services talk to each other,
not that the agents produce good patches. Prompt and model changes ship with
no before-and-after number.

Two runs also cannot be told apart by what produced them:
`run_pipeline_task.py:49` hard-codes `MODEL_NAME = "factory-pipeline"` and
writes it into every prediction; nothing records the model ids, the prompt
text or the service commits.

## Proposed outcome

- A fixed subset of 15 tasks from `benchmarks/swebench-verified-50.json` runs
  through the pipeline on a nightly job and is scored by the official harness.
- Each run stores one result file recording: model id per role, a hash of the
  prompt files, the commit of each service, the config (task list, caps), and
  per-task status, tokens, cost and duration.
- A report shows resolve rate, cost and duration over time and the change
  against the previous run; a drop past a set threshold opens an issue.
- Cost is bounded by config (task count, per-task token cap, total budget,
  per-task timeout) and the nightly estimate is written down before the
  schedule is turned on.

## Affected users and systems

Factory repo only: `scripts/benchmarks/`, `benchmarks/`, one new workflow.
Runs against a local AIFactory server, the SWE-bench harness (Docker) and
checkouts of the service repos (for prompt hash and commit SHAs). Owner: cost
approval and the runner.

## Constraints

- The driver submits a local scratch repo path to AIFactory and the harness
  needs Docker, so a GitHub-hosted runner cannot run it. It needs a
  self-hosted runner that has a local AIFactory, Docker and model credentials.
  That runner and credential are the owner's to add: the schedule lands
  disabled.
- No new third-party dependencies; reuse `run_pipeline_task.py`, `evaluate.py`
  and `report.py`. Never self-score.
- No secrets in results or logs.
- No change to the live cluster.

## Open questions

- Which runner label and which host runs it (proposed: label `factory-bench`).
  The owner supplies this when enabling the schedule.
- Regression threshold (proposed: resolve rate falls by 2 or more tasks, 13.3
  points of 15, against the previous run). Set in config, so tunable.
