# Intent: RFC-0022 Phase 2b: audit the api_get call sites and move them to protocol methods

## Problem

AIFactory, PFactory and TFactory each reach through the provider protocol with `provider.api_get(...)` at 6 sites: 5 in `apps/web-server/server/routes/github.py` (all inside `_get_provider_issue_comments`) and 1 in `services/delegation_runner.py` (`_existing_enrichment_comment`). Three of the five route sites (GitLab issue notes, Azure DevOps work-item comments, the GitHub fallback) and the delegation site read an issue's comment thread, for which the hub protocol already has `fetch_comments`. The other two (GitLab merge-request notes, Azure DevOps pull-request threads) read a pull request's comments, for which the protocol has no method. RFC-0022 section 2.2 removes `api_get`/`api_post` from the protocols, which cannot happen while callers use them (Factory#3772).

## Proposed outcome

No service calls `api_get` or `api_post` on a protocol-typed provider. Every site reads through a protocol method; the hub gains only the one method that has no equivalent (`fetch_pr_comments`). The audit of which callers depend on an integer issue number is recorded for Phase 1 (Factory#3774).

## Affected users and systems

AIFactory, PFactory, TFactory (dev); the Factory hub `shared/factory-github/` (one added protocol method, one added `IssueComment` field); the pinned-SHA drift gates in the four services. CFactory has no call site, but it re-vendors the changed hub files with the other three so the four copies agree (RFC-0022 vendoring risk: all four or none).

## Constraints

Hub protocol and vendored copies stay byte-identical behind the drift gates, and a pin must name a commit on hub main. Response shape of the comment routes does not change. Additive hub change only: nothing is removed here. No secrets handled.

## Open questions

None. Owner delegation 2026-11-17: take the recommended option; the recommendation here is to add `fetch_pr_comments` rather than drop the two pull-request fallbacks, because dropping them silently loses comments the board shows today.
