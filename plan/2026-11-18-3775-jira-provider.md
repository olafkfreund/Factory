# Plan: JiraProvider and structured Jira credential

Approved decisions (from the spec): `JiraProvider` is a `WorkItemProvider` only;
`ProviderType.JIRA`; status category mapping (Done = closed, anything else = open);
string keys; explicit Done transition, fail loudly; labels degrade on 400/403;
structured credential `{"email","api_token"}` sealed like other kinds, base URL on the
connection; CFactory flag `CFACTORY_JIRA_ENABLED` default off. No real Jira is
contacted. Coders: codex does the two test steps (contained edits), the lead does
the provider and the CFactory wiring. Steps 1-2 are the hub PR, 3-4 the CFactory PR.

## Steps

1. Hub `shared/factory-github/providers/jira_provider.py` (new), `protocol.py` (add
   `ProviderType.JIRA`), `factory.py` (new `get_work_item_provider`, jira refused by `get_provider`, `list_available_providers`),
   `__init__.py` (export), `scripts/check_factory_github_drift.py` (add the file to
   `CANONICAL_FILES`; also skip a file absent from an old pinned canonical in `check_drift` and `compared_evidence`, with a test in `tests/test_check_factory_github_drift.py`), docs line in `shared/factory-github/README.md`
   → verify `python -c` import and `ruff check`.
   Traps: vendored files are byte-checked, so edit the hub only; use plain imports.
2. Hub `tests/test_jira_provider.py` (new): MockTransport tests for each member, the
   category table with unseen statuses, pagination, 401/403/404/429, redaction,
   outgoing `fields` + token pagination (short non-final page, final page without token), ADF nodes (nested list, hard break, mention, link, null description), required-field transition failure (400 naming the field) as well as no-Done-transition, label degrade, `isinstance(WorkItemProvider)` and not `CodeProvider`
   → verify `pytest tests/test_jira_provider.py tests/test_check_factory_github_drift.py`.
3. CFactory `config.py` (flag), `git_config.py` (`JIRA`, gated `validate_provider`, key
   validation), `git_connections.py` (require base_url), `credentials.py` (structured
   encode/decode, redacted repr), `cards.py` + `git_config_ops.py` + `routes_git_config.py` +
   `mcp.py` (optional `email` on the credential write), `git_providers.py` (lazy jira branch)
   → verify `pytest` for the touched test files and `ruff`.
   Traps: do not edit the connection model beyond this; the vendored `runners/github` is untouched.
4. CFactory `tests/test_jira_connection.py` (new): flag off rejects with the flag name,
   flag on accepts, structured credential round trip, email refused on non-jira,
   response and audit never contain the token → verify `pytest tests/test_jira_connection.py`.

5. Follow-up, after the hub PR merges (not in these PRs; reported to the coordinator): re-vendor
   `runners/github/` into AIFactory, PFactory, TFactory, CFactory (base dev, pin naming the hub-main
   commit), and in CFactory add a test that builds the vendored Jira provider with a mock transport.
   coders: claude.

## Tests

`pytest tests/test_jira_provider.py` in the hub; `pytest tests/test_jira_connection.py` in CFactory;
full touched-suite plus `ruff check` and `ruff format --check` in both.

## Live smoke test (owner step, after merge and re-vendor)

Owner provides a Jira Cloud test site, email and API token for a throwaway project, sets
`CFACTORY_JIRA_ENABLED=true`, creates a `jira` connection with the site URL, stores the
credential with `email` plus the token, then: verify the connection, create an issue,
comment, apply a label, close it (transition to Done), fetch it back.

## Rollback

Revert the PRs. The flag is off by default, so nothing depends on the provider.
