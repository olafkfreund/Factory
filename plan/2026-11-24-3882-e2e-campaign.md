# Plan: Factory E2E test campaign (#3882)

This plan carries over the approved spec decisions so it can be implemented on its own.

## Decisions

- **Harness:** `scripts/e2e/` extends `scripts/parr_regression.py` (seam checks, cleanup registration) and `scripts/benchmarks/run_pipeline_task.py` (build). Reports come from `scripts/benchmarks/report.py`, unchanged.
- **Journeys:** one journey = project × surface (`cli`, `mcp`, `ui`) × model × repeat. Every stage is read back through a different surface and through the GitHub API.
- **Isolation:**
  - **GitHub:** test repos are created by the harness under the **Freundcloud** org with a scoped token. They are named `e2e-<yyyymmdd>-<P#>-<run>` and carry the topic `factory-e2e`.
  - **AIFactory and PFactory:** the AIF/PF org `factory-e2e`, with org-scoped `acw_` keys and a Keycloak test user.
  - **TFactory and CFactory:** isolated by the `e2e-` prefix only.
- **Models:** Claude, Codex and Gemini (agy) are swept on the coder and reviewer. AIFactory's per-task model comes from `StartTaskRequest.model` and `TaskMetadata.model`/`phaseModels`.
- **Fixtures:** P1 (Python CLI, canary), P2 (TypeScript API, model sweep), P3 (Go and React, parallel waves), P4 (brownfield with a planted bug), P5 (trap, must stop). Each fixture carries a hidden acceptance suite.
- **Matrix:** 18 journeys (see the spec, §5).
- **"Twice":** a repeat or paired run, plus read-back through another surface, plus the hidden suite.
- **Oracles and must-fail probes:** as in spec §6. P5, the P4 mutant and the tamper probe failing to fail turns the campaign red.
- **Cost:**
  - **Sources:** AIF `GET /api/tasks/{id}/token-usage`, `CompletionEvent.usage` and `cfactory_get_rollups`. Drift over 5% is a finding.
  - **Caps:** $15 or 60 minutes per run; $450 or 8 hours per campaign.
  - **Subscription billing:** reported as tokens only.
- **RFactory:** tested against the local `deploy/pod.sh up` instance (127.0.0.1:4180), which reads prod CFactory with an e2e read key.
- **Tracking:**
  - per campaign: an issue `e2e-campaign-YYYY-MM-DD`;
  - per failure: a child issue labelled `e2e`;
  - evidence: Actions artifacts kept 30 days, after gitleaks.
- **Cleanup sweeper:** deletes only when org = Freundcloud **and** the name matches `^e2e-` **and** the repo has the `factory-e2e` topic **and** it is more than 7 days old. It runs dry first.

## Steps

0. **Discovery and prerequisites.** The lead does this step; it has no code.
   - Post on the agent bus about prod test traffic.
   - Create the AIFactory/PFactory org `factory-e2e` through the API.
   - Model probe: start a no-op task with a Codex model id and with a Gemini model id. Confirm which provider ran from `token-usage` and the logs.
   - Record the G4 drift on #3882: CFactory `/api/usage`, and the MCP names in `apis/*.mcp.md`.
   - **Owner tasks:**
     - create the Keycloak test user `e2e-runner` with TOTP;
     - create a fine-grained GitHub token for the Freundcloud org with `administration:write` and `contents:write`;
     - put both in agenix, and give the names to the lead.

   Verify: the probe table and the owner's secret names are posted on #3882.
   Trap: never print or decode secret values.

1. **`shared/factory-cli/factory_cli/`: parity verbs, each with a `factory mcp` twin through one shared handler.** The verbs:
   - `project list|add`, using `/api/mcp-stdio/projects` on AIF, PF and TF;
   - `approve|reject <pf:|af:>`;
   - `retry|archive <af:|tf:>`;
   - `card create|move|list|run`, a JSON-RPC client to CFactory `/mcp`.

   Server proxies are added where they are missing: AIF `reject-plan`, PF `reject`, the AIF archive proxy. If the step 0 probe shows models are not routed to providers, add a `provider` field to `StartTaskRequest`.

   Verify: `pytest shared/factory-cli`, the ratchet, and the jscpd budget.
   Traps:
   - `_vendor/**` is excluded from jscpd;
   - errors returned to clients use `client_error`, never `str(exc)`;
   - every new route uses org-scoped auth.

2. **`scripts/e2e/` harness core.** It contains:
   - `config.py` (hosts, caps, guards);
   - `journey.py` (the stage runners S1–S5 and X);
   - `surfaces/{cli,mcp}.py`;
   - `readback.py`;
   - `cost.py` (three sources and caps);
   - `cleanup.py` (registry and sweeper with `--dry-run` as the default);
   - `run.meta.json` output that matches the `report.py` schema plus `surface`, `project` and `stage_results`.

   Unit tests go in `tests/e2e/unit/`:
   - the guard refuses a non-`e2e-` repo and a non-Freundcloud org;
   - the cap aborts the run;
   - read-back mismatch fails the stage.

   Verify: `pytest tests/e2e/unit` and the ratchet.
   Trap: the ratchet sees only committed changes.

3. **`tests/e2e/fixtures/P1`, `P5`.** Each has a starter tree, an intent/spec/plan triple, and a hidden suite under `tests/e2e/hidden/` that is never pushed to the test repo.

   Verify: the hidden suite passes on a reference solution and fails on the starter.

4. **Minimum viable run.** The lead runs it:
   - P1 through the CLI × 2 and P1 through MCP × 2 on Claude;
   - P5 through the CLI.

   Expected results:
   - P1 is green on all oracles;
   - P5 stops in Needs you;
   - the cap test ($0.01) aborts cleanly;
   - the sweeper dry run lists only e2e repos;
   - teardown is verified.

   Verify: the results table is posted on `e2e-campaign-<date>`. Any failure becomes a child issue.

5. **`scripts/e2e/surfaces/ui.py`.** A Playwright adapter that reuses the Keycloak/TOTP login from `TFactory/portal_testing/run.py`. It uses role and label selectors and takes screenshots on failure. A UI red is confirmed through MCP before anything is filed. It then runs P1 and P5 through the UI.

   Verify: P1 through the UI is green; P5 through the UI stops.

6. **`tests/e2e/rfactory/`.** Codex writes the API half:
   - roles;
   - standup buckets with no AI call;
   - review 404 isolation;
   - freshness;
   - the CFactory#583 probe.

   agy writes the UI login and the weekly bot smoke test.

   Verify: the suite passes against local RFactory during a P1 run.

7. **Fixtures P2, P3, P4.** Add the P4 mutant (re-planting the bug must turn the verdict red) and the S2 tamper probe.

   Verify: each hidden suite passes on its reference solution and fails on its starter.

8. **Model sweep and audit.**
   - P2 × {Claude, Codex, Gemini} × 2 through the CLI.
   - Produce the cost report.
   - Fable's rules and skills audit, second-scored by Codex on 20%.

   Verify: the report and audit are posted on the campaign issue.

9. **Campaign #1** (all 18 journeys), followed by triage and the report. Then switch on the nightly run (seam gate plus P1 through the CLI) and the weekly campaign in `.github/workflows/parr-nightly.yml` and a new `e2e-weekly.yml`.

   Verify: the first scheduled runs are green or triaged.

Every step that edits files follows the same flow:
1. a PR on `feat/3882-*`;
2. review by the reviewers who did not write it, plus a fresh Opus reviewer, for at most 2 rounds;
3. CI, then merge with `--match-head-commit`.

## Tests

- **Unit:** `pytest tests/e2e/unit shared/factory-cli`.
- **Integration:** the minimum viable run (step 4) and campaign #1 (step 9), together with the self-checks:
  - P5 and the P4 mutant must fail;
  - the tamper probe must return 4xx;
  - read-back must agree;
  - the cap test must abort.

## Rollback

- **Workflows:** disable `e2e-weekly.yml` and the nightly P1 job.
- **CLI verbs:** they are additive, so revert the PR.
- **Leftover test resources:** run the sweeper live. It deletes only e2e repos and the `factory-e2e` org's projects.
