# Plan: Factory E2E test campaign (#3882)

This plan is self-contained. It carries every approved decision from the spec.

## Decisions

### Harness

- **New package `scripts/e2e/`.** It reuses helpers only:
  - from `scripts/parr_regression.py`: HTTP/auth helpers and the seam checks. **Never `--full`**, which targets `aifactory-demo`. Its in-memory cleanup is not used either.
  - from `scripts/benchmarks/run_pipeline_task.py`: the poll and diff helpers only.
- **Report.** The new `scripts/e2e/report.py` reads the record format of `benchmarks/report.py`. It adds `surface`, `project`, `stage_results` and `billing_mode`, and the median cost per build that passes the hidden suite.
- **Journeys.** One journey is a project × surface (`cli`, `mcp`, `ui`) × model × repeat.
- **Read-back** goes through REST or the remote MCPs (`aifactory.*`, `pfactory.*`, `cfactory_*`) and the GitHub API. `factory mcp` shares handlers with the CLI, so it never counts as read-back.
- **Hosts.** Pin `*.freundcloud.org.uk` explicitly and ignore CLI env and config overrides.

### Safety

- **Registry.** `evidence/<campaign>/registry.jsonl` is append-only. Each entry is written before the create returns and holds:
  - the repo `node_id`, `id` and `full_name`;
  - the project IDs for each service;
  - the PF session, AIF task and TF spec IDs;
  - the CF card key.
- **`guard.py` checks every mutation** (start, approve, reject, move, run, archive, delete, teardown) on every service. A mutation is allowed only if both hold:
  1. the target ID is registered;
  2. a live re-read shows it still belongs to the registered repo.
- **GitHub uses agenix `api-github-token`.** It is a broad classic PAT. The guard also requires:
  - the owner is `Freundcloud`;
  - the name matches `^e2e-\d{8}-P[1-5]-\d+$`;
  - the topic `factory-e2e` is present.

  The token is read from its file and never logged.
- **Sweeper.** It deletes registered entries only, and only when they are older than 7 days. Each delete is followed by an absence check. Unregistered `e2e-` repos are reported, never deleted. PF sessions are closed and recorded as retained. `--dry-run` is the default.
- **Isolation.**
  - AIF, PF and TF use the org `factory-e2e` with org-scoped `acw_` keys.
  - The CFactory key is global, so every card write is guarded by the registry.
  - Multi-tenant flags are off on prod; step 0 confirms this.
- **Keys.** They are minted with exactly the scopes used:
  - `api` for REST;
  - `project:write`, `task:write` and `task:merge` for `/api/mcp-stdio` writes;
  - `mcp:read`/`mcp:write` for the remote MCP.

  An auth preflight (one read and one dry write per operation) must pass before any journey.

### Models

- `/from-plan` ignores `request.model`. The model comes from the **signed plan's `execution` block**: `phaseModels` sets the coder and QA reviewer to different models.
- The sweep covers Claude, Codex and Gemini (agy). PF planning and TF runs stay at their defaults and are recorded.
- Runtime evidence of provider and model is required for each phase.

### Fixtures

Each fixture lives in `tests/e2e/fixtures/P#/` and holds a starter, a triple with an execution profile, and a reference solution. Its hidden suite lives in `tests/e2e/hidden/P#/` and is never pushed.

| ID | Project | Size | Purpose |
|---|---|---|---|
| P1 | Python stdlib CLI `wordfreq` | XS | canary |
| P2 | TypeScript Express API, 3 endpoints | S | model sweep |
| P3 | Go service + React page | M | parallel waves, browser lane |
| P4 | Brownfield: planted bug, failing test, ambiguous requirement | S | review gates, handback, mutant |
| P5 | Contradictory criterion | XS | trap: must stop. It passes if PFactory review rejects it with a contradiction-specific finding **or** AIFactory stops in Needs you. It fails if it is merged or goes green |

### Matrix: 19 journeys

| Slice | Journeys | n | Cap per run |
|---|---|---|---|
| Surface sweep | P1 × {cli, mcp, ui} × Claude × 2 | 6 | $15 / 60m |
| Model sweep | P2 × cli × {Claude, Codex, Gemini} × 2 | 6 | $15 / 60m |
| Depth | P3 × mcp × {Claude, Codex} | 2 | $25 / 90m |
| Brownfield | P4 × ui × {Claude, Gemini} | 2 | $25 / 90m |
| Negative | P5 × {cli, ui} × Claude | 2 | $15 / 60m |
| Ablation | P1 × cli × Claude, rules and skills off | 1 | $15 / 60m |

"Twice" means:
- a repeat (P1, P2) or a pair (P3, P4 by model; P5 by surface);
- independent read-back;
- the hidden suite on the merge SHA.

Known gaps are published with every report: surface and model are never crossed on one fixture, P3 has no Gemini run, and P4 has no Codex run. A UI result that disagrees with read-back is a **surface failure**.

### Oracles

Every probe needs its **specific failure reason**. An auth error, a missing route or an infra error never satisfies a must-fail probe. Every stage has a deadline.

| Stage | Pass | Must-fail probes (each built in step 2) |
|---|---|---|
| S1 | Registered repo with branch protection. One project per service in the e2e org. Exactly one CF card | (a) replay onboarding, still 1 + 1; (b) unreachable registered repo gives an explicit access error |
| S2 | `ingest-approved` (PF ≥ 0.9.4), approve, emit, then AIF `/from-plan` accepts. Review finding ≥ 1 on P4/P5 | (c) artifact byte changed with the original blob SHA gives PF's integrity rejection; (d) contract byte changed gives AIF's signed-plan rejection; (e) replay gives the dedup response and no new AIF task |
| S3 | Terminal and green. Non-empty diff only in the plan's files (excluding intent/spec/plan and lockfiles). Review recorded. Runtime reviewer model ≠ coder model | (f) empty or docs-only diff; (g) usage still zero at its deadline, reported as a "missing usage" finding |
| S4 | PR merged by the service identity (from the PR timeline). Required checks green on the merged head. Links the triple | (h) a head pushed after the verdict makes the merge refuse as stale, then a fresh verdict, then merge |
| S5 | Verdict on the **merge SHA** with all 5 signals. Hidden suite green on the same SHA | (i) a controlled 0-tests SHA gives the specific reason; (j) a verdict-SHA mismatch is rejected; (k) **P4 mutant**: re-plant the bug on a probe branch with auto-repair off, and the verdict must be red naming the behaviour |
| X | Expected events (producer × phase × journey, handbacks included) present in order. Journey cost = sum of stages ±1%. No anomaly references a registered card. Rollups and anomalies are filtered to the registry | (l) re-delivering the same event ID applies it once; (m) CFactory#583: two registered repos with issue #1 do not bleed into each other. The dropped-event probe is **deferred** (no safe seam) and reported as a gap |

### Cost

- **Sources:**
  - AIF `GET /api/tasks/{id}/token-usage`, polled until its deadline;
  - `CompletionEvent.usage`;
  - CF `/api/tokens` and `/api/rollups`, filtered to the registry;
  - provider logs, where they exist.
- **Drift** above 5% between sources is a finding.
- **Subscriptions** are reported as tokens only.
- **Caps:**
  - The budget is reserved before dispatch.
  - At the cap, the harness stops the task and **confirms** it is stopped. If the stop is unconfirmed, the lane blocks and the run is filed.
  - **Campaign:** $450 for the 19 journeys ($325 at the caps), 3 lanes, 8 hours.
  - Build-out runs have the separate caps named in each step.

### RFactory

- **Roles** come from the email allowlists, checked against `x-forwarded-email`. Keycloak roles are not used.
- **Role tests** run against `web/server.js` on loopback, with a crafted header for each role, and each role must produce a role-specific observation.
- **One SSO check** runs through `deploy/pod.sh up` as `e2e-runner`.
- **Isolation:** its own config directory and Claude home, writes off, and a runner where the fixed `rfactory` pod name does not collide.
- **Standup** calls are serialised, because the endpoint returns 409 when busy.
- **Review** returns 404 for an out-of-scope card and 200 for an in-scope control card.
- During a P1 run that is kept for this purpose, its card must be visible.

### Management

- **Tracking:**
  - one issue per campaign, `e2e-campaign-YYYY-MM-DD`;
  - one child issue per failure (`e2e`, stage);
  - evidence, including the registry, uploaded as Actions artifacts after gitleaks and kept 30 days.
- **Roles:**

  | Who | Builds | Runs |
  |---|---|---|
  | Claude | — (leads, merges) | MCP surface; triage |
  | Codex | harness, server and CLI changes | CLI surface and hidden suites |
  | agy | UI runner and fixtures | UI surface |
  | Fable | — | oracle review, rules audit, adjudication |

  The reviewer is never the builder.
- **Triage classes:**
  - product bug (blocks a release);
  - surface gap (blocks a release);
  - model or skill drift;
  - infra or flake (needs 2 repros).

## Amendment (owner, 2026-11-24): use what exists, no owner setup

The owner asked for the setup to run without them in the loop. The following replace the parts of Decisions and step 0 that called for new orgs, keys and a test user:

- **Keys.** The existing keys in `~/.aifactory/.token`, `~/.pfactory/.token`, `~/.tfactory/.token` and `~/.cfactory/.token` are used. `factory doctor` showed read=ok on all four on 2026-11-24. No `factory-e2e` org is created. The guard's org check compares against the org recorded for each resource when it was onboarded, not a fixed `factory-e2e`. Isolation relies on the registry guard, the `e2e-` repo prefix and the topic.
- **UI surface.** The lead drives the owner's signed-in Chrome through claude-in-chrome, with GIF evidence. There is no Keycloak `e2e-runner` and no Playwright TOTP login. Step 5's Playwright adapter is deferred until a test identity exists.
- **RFactory.** Role tests run against `web/server.js` on loopback, with made-up allowlist emails in an isolated config. The SSO check through `pod.sh` is dropped.
- **Repo owner** (owner, 2026-11-24, after the first live runs): test repos go under the owner's personal account `olafkfreund`, not the Freundcloud org. They are created public with `POST /user/repos` (owner, 2026-11-24) until Factory#3890 lets PFactory and TFactory clone private repos; they hold fixture code only and are deleted after each run. The reason: AIFactory's clone credential cannot read private Freundcloud repos ("Clone failed"), and the Free plan blocks branch protection there. The other safeguards stay the same: the `e2e-` name, the `factory-e2e` topic and the registry.
- **Runtime trap.** uv-provided Python on this host has no CA bundle. Set `SSL_CERT_FILE=/etc/ssl/certs/ca-certificates.crt`.
