# Plan: hub-owned shared shell (#3876)

The spec is the contract: the layout, the props, the file list, what gets
deleted and the gates. **Revision 1 (R1–R6) at the end of the spec is
binding and wins on any conflict.** Steps 1–3 are the hub PR (Factory). Step 4 is the
first portal, TFactory, as its own PR in that repo. AIFactory, PFactory,
CFactory and RFactory follow as the same step 4 shape, one PR each, after the
owner's side-by-side check.

## Steps

1. **`shared/factory-ui/shell.css`:**
   - the top bar, strip, sidebar (rail and drawer), page head and state
     components, per the spec;
   - tokens only, a 12px floor;
   - light and dark come from the tokens.

   → verify: `python3 scripts/check_banned_constructs.py --enforce-small-text`
   on the file; `python3 scripts/check_token_contrast.py`.
2. **`AppShell.tsx`, `ProjectSwitcher.tsx`, `PipelineStrip.tsx`, `WorkCard.tsx`, `WorkColumn.tsx`, and the plain-CSS port of `PortalSwitcher`/`CommandPalette` (R2):**
   - React 19, no dependencies beyond react;
   - the props in the spec;
   - keyboard: ⌘K for search, `/` to focus the project search, Esc to close;
   - ARIA: the switcher is a combobox and the strip a toolbar;
   - the sidebar collapse state is a prop, controlled by the portal.

   Generalise CFactory `PipelineStrip.tsx` and its `.pstrip` CSS.
   `WorkCard`'s collapsed, active, failed and expanded states follow the
   spec, and `shell.css` (step 1) carries the `f-card` styles.
   → verify: `tsc --noEmit` with CFactory's strict tsconfig options (R2) and
   React 19 types from a portal checkout's node_modules.
3. **Drift gate** (`scripts/check_factory_ui_drift.py`): add the new
   canonicals and destinations, and the RFactory CSS-only subset; update the
   tests and README. The shell entries go in the canonical set but are not
   required until a portal's pin includes them (the existing `NOT_YET_PINNED`
   pattern), so no portal breaks on merge.
   → verify:
   ```
   pytest tests -q
   ```
   Also run the drift check against all four portals at their current pins;
   all must pass.
4. **TFactory adoption** (separate TFactory PR, after the hub PR merges and
   after #1665):
   - vendor the files;
   - wrap `App.tsx` in `AppShell`;
   - make the nav items from the current sidebar;
   - strip stages: Plan, Generate, Execute, Report, from the existing
     pipeline data;
   - move project settings to `/p/<slug>/settings`;
   - delete `ProjectTabBar`, `SortableProjectTab`, the rail panel and the
     sidebar selector;
   - add the `settings` and Preferences routes and move every `onSettingsClick` caller (R5);
   - pass the status badges and RateLimitIndicator via `topbarStatus` (R3);
   - render the board's spec cards with `WorkCard` in `WorkColumn`: collapsed for
     done/triaged, failed with Re-run/Dismiss;
   - write an inventory of old shell actions and where each now lives, in the
     PR body.

   → verify:
   ```
   npm -w apps/frontend-web run typecheck
   npm -w apps/frontend-web run test
   npm -w apps/frontend-web run lint
   npm -w apps/frontend-web run build
   ```
   Then the drift gate at the new pin, and the browser test at 1280px and
   390px, light and dark.

Traps:
- vendored files are never edited in a portal;
- the hub's Python ratchet covers scripts and tests;
- jscpd budget: no copied test headers;
- TFactory's ratchet and `ruff format` (CI pins);
- TFactory lint stays at 0 errors.

## Tests

As each step lists. The owner side-by-side check happens at TFactory before
the other portals.

## Rollback

- Hub: revert. Portals keep their pinned copies.
- A portal: revert its adoption PR.

## Later steps (one PR each, after the owner's TFactory check)

5. AIFactory: step 4's shape. `WorkCard` sits inside the existing
   `SortableTaskCard` wrapper; the memo is kept.
6. PFactory: step 4's shape. The strip uses three buckets (R4); the ambient
   CSS is deleted.
7. CFactory:
   - vendor the full subset except the bridge, and add its first drift
     workflow;
   - switch to `.dark`;
   - `AppShell` with the interactive strip;
   - Pipeline cards use `WorkCard`;
   - Planning and Backlog get the `f-card` styles only (R4).
8. RFactory: tokens and shell CSS, top-bar markup, `data-portal="meet"` and a
   drift workflow (R6).
