# Plan: finished builds reach a human as a pull request

## Approved decisions (self-contained)

- All code changes are in **AIFactory**, branch `feat/2586-merger-closes-loop`
  off `origin/dev`, extending `apps/web-server/server/services/merger.py`.
  No hub module, no CFactory change (CFactory does not read `reviewReason`).
  One config change in **factory-gitops**.
- **No auto-merge.** `AIFACTORY_AUTO_MERGE` is not read or changed. No
  force-push anywhere. The QA agent never records a pass it did not observe
  (#1496); this change does not touch QA.
- The merger **looks up the PR in every state first** (`gh pr list --head
  <branch> --state all`). Prefer OPEN, else the most recent PR. OPEN →
  `already_open`. MERGED → `merged`, no new PR. CLOSED → `closed`, no new PR.
  A failed query → skip `open_pr_check_unmeasurable`.
- The merger **measures the local branch** (`refs/heads/<branch>`, falling
  back to `origin/<branch>`) against a fresh `origin/<base>`:
  `ahead_by` via `rev-list --count base..ref`, `changed_files` via a
  three-dot diff, plus an `unpushed` count. Unmeasurable → `(None, None)`.
  PRs are opened with the existing `pe.create_pr`, which pushes without force.
- **Status follows the PR**, written through `task_control.write_control`
  (`updated_by="merger"`), **only when the current status is
  `human_review`**:
  `opened`/`already_open` → `human_review`/`awaiting_merge`;
  `merged` → `done` + clear the reason; `closed` → `human_review`/`pr_closed`;
  `no_content` with no PR → `human_review`/`no_work`; other skips → no write.
  These are new `ReviewReason` values, not new `TaskStatus` values.
  `plan_review` already exists and is never written by the merger.
- **Build-end trigger:** `run_terminal_completion` calls
  `merger.process_one(...)` after the PR endgame block, in its own
  best-effort `try`, only when `is_completed`.
- **Backstop:** an in-process `merger_loop` modelled on
  `stale_reaper.reaper_loop`, started in `main.py`'s lifespan, not a
  CronJob. Reasons: (a) a CronJob would need a new write-scoped machine
  credential; (b) the spec tree is on an RWO local-path PVC, so a CronJob pod
  off the node would see nothing and exit green (the same reason the reaper
  is in-process, `main.py:228`). Env: `AIFACTORY_MERGER_SWEEP` (off by
  default), `AIFACTORY_MERGER_SWEEP_DRY_RUN` (default **true**),
  `AIFACTORY_MERGER_SWEEP_INTERVAL_S` (default 900). The GET report exposes
  `last_tick_at`.

## Steps

Each step is one commit on the AIFactory branch. Tests go in the same commit
as the code.

1. **`merger.py`: PR lookup in every state.** Replace `_find_open_pr` with
   `_find_pr(...) -> (measured, number, state)`. In `_decide`, return
   `{"action": "merged"|"closed", "pr": n}` before any measuring.
   → verify: new tests in `apps/web-server/tests/test_merger.py`: a MERGED
   PR opens nothing even with the local branch ahead; a CLOSED PR opens
   nothing; OPEN is preferred over an older MERGED; a failed `gh` query is
   still unmeasurable.
2. **`merger.py`: measure the local branch.** Rewrite
   `_branch_ahead_and_changed` to use the local ref (with fallback), the
   three-dot diff, and to return `unpushed`. Add it to the
   `would_open`/`opened` dicts.
   → verify: test that a local branch 3 commits ahead with origin at base is
   `would_open` with `unpushed == 3` (today it is `no_content`). **Mutation
   check:** point the measurement back at `origin/<branch>` and confirm this
   test fails, then restore it.
3. **`merger.py`: `_sync_status` and `process_one`.** `_sync_status(spec_dir,
   result)` applies the mapping above through `write_control`, guarded by
   `read_control(spec_dir).get("status") == "human_review"`. `sweep` calls
   it for every non-dry-run result. `process_one(project_id, project_path,
   spec_dir)` = `_process_spec(dry_run=False)` + `_sync_status`. The report
   gains `merged`, `closed` and `status_written` counts. Dry runs never
   write status.
   → verify: tests for each mapping row; `in_progress` and `done` are not
   touched; a dry run writes nothing (the file's mtime is unchanged).
4. **`completion_orchestration.py`: build-end call.** After the endgame

   → verify: tests that `process_one` is called once when `is_completed`

## Rollback

- **Runtime, instant:** set `AIFACTORY_MERGER_SWEEP=false` (or back to
  `DRY_RUN=true`) in factory-gitops. The build-end call obeys
  `AIFACTORY_AUTO_PR` like today's endgame; set that to false to stop all
  PR creation.
- **Code:** revert the AIFactory PR; nothing depends on it.
- **Data:** the merger only writes `status`/`reviewReason` in
  `task_control.json`, tagged `updatedBy: "merger"`. To undo, set those
  specs back to `human_review` and clear the reason. PRs it opened are
  ordinary PRs and can be closed by hand. No branch is ever force-pushed or
  deleted.
