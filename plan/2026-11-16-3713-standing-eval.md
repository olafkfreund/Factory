# Plan: Standing nightly evaluation

Approved decisions (from spec): config in `benchmarks/nightly-config.json`
(tasks, caps, `regression_drop_tasks` 2, `min_paired` 10, `baseline`
outcomes for the 15 ids from `docs/benchmarks/2026-07-baseline.md`);
`provenance.py` records `models_configured` (ast-read `DEFAULT_PHASE_MODELS`,
env override) and per-task `models_observed`, prompt hash (sha256 over sorted path+bytes of `prompt_globs`),
commits (`git rev-parse HEAD` per `<SERVICE>_DIR`, null if absent) and a
label `factory-pipeline-<8 hex>` replacing `MODEL_NAME`; `nightly_eval.py`
with `run` / `compare` / `report`; results in `NIGHTLY_RESULTS_DIR` plus a
workflow artifact, file name = unique `run_id` timestamp, run-scoped
scratch/predictions dirs; regression = resolved drop >= 2 on the paired set
(both runs scored; harness-error, skipped and driver errors excluded; needs
>= 10 paired); exit 2 from the driver still gets scored; budget = task
count, per-task timeout (+ best-effort `POST /api/tasks/{id}/stop`), a stop
between tasks at `total_token_budget` (not a hard ceiling), `over_cap`
flag; issue criterion 1 stays open until the owner enables the schedule; workflow `bench-nightly.yml` on a self-hosted
`factory-bench` runner with `schedule` commented out (owner enables).

## Deviations (found in final review, same commit as the code)

- Exit codes: `run` and `compare` exit 4 when nothing could be graded or paired
  coverage is too low (red job, no regression issue); regression stays 3.
- Wall time is measured around the whole run, not summed from task durations.
- A per-task setup or problem-fetch failure is recorded as `driver_error`
  instead of losing the run record.
- `run_pipeline_task.py` also accepts camelCase `totalTokens`/`totalCostUsd`
  (AIFactory aggregate) and treats an empty `AIFACTORY_URL` as unset.
