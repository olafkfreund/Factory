# Plan: Keycloak post-broker-login conditional OTP

Carries the approved spec unchanged: new default-`audit` CronJob `keycloak-broker-otp` in factory-gitops (modes audit, install, bind, unbind); flow `post-broker-otp` = CONDITIONAL sub-flow (`conditional-user-configured` 10, `auth-otp-form` 20) at priority 10 plus `allow-access-authenticator` 20; declarative JSON in realm-export format; the job refuses drift on install/bind, `unbind` works regardless; throwaway-container e2e; nothing applied to the live realm.

Deviation to note: the lead built the app in the worktree as a prototype before this plan was approved, because the flow (priorities, the `allow-access-authenticator` step) can only be found by running it. Nothing was committed or pushed before approval; the steps below are what gets committed.

Repo: factory-gitops (base `main`), branch `feat/3781-broker-otp`. Artifacts: Factory PR (base `main`).

## Steps

1. `apps/keycloak-broker-otp/{application.yaml,manifests/{cronjob.yaml,kustomization.yaml,keycloak-broker-otp.sh,post-broker-otp.realm.json}}`: the app, mode default `audit`, image pinned by digest as in `keycloak-mfa` → `kustomize build apps/keycloak-broker-otp/manifests`.
   Traps: image digest identical to `keycloak-mfa`; no new secret; do not use the `master` realm.
2. `apps/keycloak-broker-otp/manifests/e2e-local.sh`, `.github/workflows/keycloak-broker-otp-e2e.yml`: throwaway-container test, paths-filtered, not required → `bash apps/keycloak-broker-otp/manifests/e2e-local.sh` prints `ALL PASS`.
   Traps: container only, never the cluster; pinned action SHA as in `keycloak-mfa-test.yml`.
3. `docs/keycloak-sso.md` "MFA": add the job, owner checklist (master console login, break-glass account, audit, install, bind, then the throwaway GitHub login), rollback (`unbind`; master-realm credential reset), replace the "Known limits" paragraph with the tested facts (append verified on 26.1; pending `CONFIGURE_TOTP` reaches enrolment; the flow's existence) → `mkdocs`/link check as the repo's CI does; read once.
   Traps: no secret values; the owner's live test stays open.

## Tests

- `bash apps/keycloak-broker-otp/manifests/e2e-local.sh` → `ALL PASS`, with each of these assertions (each fails the script if it does not hold): baseline unchallenged; install idempotent and does not bind; realm JSON equals the live flow; bound: user without OTP passes, user with OTP is challenged, wrong code refused, right code accepted; unbind restores the plain login; `requiredActions+=` appends, keeps `UPDATE_PASSWORD`, no duplicate; pending `CONFIGURE_TOTP` reaches the enrolment form with the flow unbound and bound; `bind` refuses to replace a different post-broker flow; with a hand-edited flow `install` and `bind` refuse, `audit` reports `drift`, and `unbind` still works.
- `kustomize build apps/keycloak-broker-otp/manifests` and `sh apps/keycloak-mfa/manifests/test.sh` → still pass.
- PR checks green on the final head SHA; `manifest validation` covers kubeconform and Kyverno.

## Rollback

The app is `audit` by default and writes nothing. If `bind` was applied: first set `BROKER_OTP_MODE: unbind` (or `audit`) in git and let Argo sync; a direct `kcadm.sh update identity-provider/instances/github -r factory -s postBrokerLoginFlowAlias=` is only an emergency step and MUST be followed by that git change, because a CronJob still set to `bind` re-binds on its next run. A user locked out by a lost authenticator is reset in the `master` realm admin console. Revert the PR to remove the app.
