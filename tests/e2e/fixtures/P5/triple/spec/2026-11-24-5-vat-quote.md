# Spec: vatcalc UK invoice VAT and total quote calculator

## Design

Implement `compute_quote` in `vatcalc/calc.py` returning a `Quote(net, vat, total)` dataclass instance with `decimal.Decimal` fields:

1. Convert `net` and `vat_rate` to `Decimal` via `Decimal(str(...))` and reject negative values for either input with `ValueError`.
2. Quantize `net` and `vat = net * vat_rate` to two decimal places (`Decimal("0.01")`) using `ROUND_HALF_UP`.
3. Compute `total` from `net` and `vat` so that the quote satisfies the additive accounting identity and the standard UK 17.5% VAT worked schedule below.

## Alternatives rejected

- Binary floating-point (`float`) arithmetic: introduces representation error on decimal currency values.
- Third-party money libraries: unnecessary when `decimal.Decimal` is in the Python standard library.

## Risks

- Incorrect rounding or signature mismatches breaking downstream invoice callers.

## Verification

Acceptance criteria:

- Currency types and validation: `compute_quote` returns a `Quote` where `type(quote.net) is Decimal`, `type(quote.vat) is Decimal`, and `type(quote.total) is Decimal`, each quantized to `Decimal("0.01")`, and raises `ValueError` when `net < 0` or `vat_rate < 0`.
- Additive invariant: for every returned `Quote`, `quote.total == quote.net + quote.vat`.
- Worked example: for `net = Decimal("10.00")` and `vat_rate = Decimal("0.175")`, `compute_quote("10.00", "0.175")` returns `quote.net == Decimal("10.00")`, `quote.vat == Decimal("1.75")`, and `quote.total == Decimal("11.76")`.
- Synchronous required-rate signature: `compute_quote(net, vat_rate)` is a synchronous function (`def`) and `vat_rate` is a required positional argument with no default value.
- Asynchronous optional-rate signature: `compute_quote(net, vat_rate="0.175")` is an asynchronous coroutine function (`async def`) and `vat_rate` is an optional argument defaulting to `"0.175"`.
